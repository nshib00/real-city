# Нагрузочные сценарии

Запускайте на отдельной тестовой базе. Для чтения чанков и viewport: `k6 run tests/k6/world.js`. Сценарий команд включается через `TOKEN=... ENABLE_MUTATIONS=1`; выделите тестовому игроку ресурсы и свободную полосу тайлов (`PLACEMENT_TILE_START`, `PLACEMENT_TILE_Y`, `BUILDING_TYPE`). Коды 4xx показывают отказы бизнес-правил и лимитов, поэтому сравнивайте их отдельно от 5xx и задержек.

Для WebSocket fanout: `TOKEN=... WS_VUS=50 k6 run tests/k6/ws.js`. Чтобы измерить фактическую рассылку, параллельно создавайте события в подписанном чанке; сценарий считает корректные полученные envelopes. Для тиков симуляции снимайте `/metrics` до и во время нагрузки и сравнивайте длительность, просроченные действия и dropped events. Повторите прогоны с 1 и 4 worker, затем сохраните p50/p95/p99, RPS, число соединений и ошибки вместе с конфигурацией машины.

Параллельно с другими сценариями запускайте `k6 run tests/k6/simulation.js`: он проверяет свежесть heartbeat и записывает среднюю длительность тика по счётчикам `/metrics`.

Для профилирования задайте `PPROF_ADDR=127.0.0.1:6060` при запуске API и используйте `go tool pprof http://127.0.0.1:6060/debug/pprof/profile?seconds=30` на той же машине. Адрес не должен быть доступен с внешнего интерфейса; API отклонит такой запуск. В браузере `performance.getEntriesByName('real-city:map-ready')` показывает время до готовности карты.
