# Проверка живого API

Из корня проекта:

```bash
REAL_CITY_API_URL=http://127.0.0.1:18080 python3 tests/e2e/api/smoke.py
make gameplay-restart-test
```

Первый сценарий регистрирует двух игроков, размещает ратуши рядом на общей карте, проверяет replay строительства после refresh токена, инвентарь, монстров, прямую атаку стартовым оружием и WS upgrade. Дорогостоящий призыв монстра не предполагается доступным игроку со стартовыми 50 монетами.

Второй сценарий запускает отдельный test Compose с миграциями, проверяет общий мир, союз и приглашение, доставку сообщения по настоящему WebSocket, серверную позицию прочтения, казну, резерв рыночной заявки и таймер ремонта. Затем перезапускает backend со встроенной симуляцией, сохраняя PostgreSQL/Redis/volumes. После рестарта проверяет данные, возврат резерва ровно один раз, завершение ремонта и возврат рабочих, исключение из союза с отзывом доступа и выход последнего лидера. Временный checkpoint с токенами имеет права 0600 и удаляется скриптом.

Сценарии изменяют тестовый мир и оставляют созданных игроков/объекты для диагностики. Не запускать их на production. Для внешнего стенда шаги можно выполнить отдельно:

```bash
python3 tests/e2e/api/gameplay_restart.py --prepare /tmp/real-city-checkpoint.json
# Перезапустить API и worker выбранного тестового стенда, сохранив БД.
python3 tests/e2e/api/gameplay_restart.py --verify /tmp/real-city-checkpoint.json
rm /tmp/real-city-checkpoint.json
```

Проверка транзакций настоящей БД (после миграций):

```bash
cd backend
TEST_POSTGRES_DSN='postgres://real_city:real_city@localhost:5432/real_city?sslmode=disable' go test ./internal/adapter/postgres -run TestSocialPersistenceAndMarketAtomicity
```

Полный браузерный маршрут, производство/апгрейды всех типов и многопользовательская release-приёмка остаются отдельными критериями 21.15, 25.10 и 26.6. Наличие скрипта не означает успешный живой прогон.
