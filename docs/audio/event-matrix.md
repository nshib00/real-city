# Матрица игровых событий и звуков

Состояние контракта на 23.10.2026. `sound_id` ниже обозначает намерение, а не готовый файл: звуковой движок и ассеты относятся к следующим фазам. Источники сверены с `frontend/src/features/`, `frontend/src/game/IsoMap.tsx`, `frontend/src/shared/api/`, `shared/events/` и `backend/internal/service/events.go`.

## Правило подтверждения

Локально сразу звучат только нейтральные действия интерфейса: кнопка, вкладка, открытие панели, смена выделения и размещение предварительного контура. Нажатие «Построить», «Собрать», «Атаковать» или «Отправить» не означает успех. Трата, награда, попадание и разрушение звучат после успешного ответа API или однозначного WS-события. Ошибка ответа получает `ui.action.invalid` либо `ui.resource.insufficient` после разбора кода; один отказ не должен дать оба сигнала. Инвалидация кеша и загрузка списка не являются результатами действия.

Для собственного действия выбрать один источник: успешный ответ API. Последующий WS-echo меняет состояние, но не повторяет звук. Для чужих и автоматических действий — WS с дедупликацией по `event_id`; повтор после reconnect молчит. Удалённый мир слышен только в видимой или близкой области камеры. Личные критичные уведомления могут звучать вне экрана; у них нет пространственной панорамы. `chunk_id` сам по себе не равен видимости объекта.

Обозначения: **есть** — подтверждение и нужные данные сейчас доступны; **частично** — требуется сравнение предыдущего состояния или дополнительное поле; **нет** — безопасно озвучить результат сейчас нельзя. Координата берётся из подтверждённого объекта или ответа, а не из команды клиента.

| Действие / поверхность | Подтверждение API или WS | `sound_id` | Координата | Кому слышно | Готовность и ограничение |
|---|---|---|---|---|---|
| Кнопка, вкладка, панель, выделение (`BuildMenu`, `Inspector`, общие UI) | Локальное явное действие | `ui.click`, `ui.tab`, `ui.panel.*`, `ui.select.*` | Не нужна | Только себе | **есть**; никакого звука на hover, перетаскивание и ререндер |
| Неверное действие / отказ API | Ошибка mutation или `placeBuildingRequest` | `ui.action.invalid` / `ui.resource.insufficient` | Не нужна | Только инициатору | **частично**; различать нехватку по структурированному коду, если доступен |
| Размещение здания (`BuildMenu`) | `placeBuildingRequest` → `building`; WS `world.building.placed` | `build.placed`, для дороги/стены `build.road.placed` / `build.wall.placed` | `building.tile_x/y` в API; `building.Tile` в WS | Инициатору по API; соседям вблизи по WS | **есть** для размещения; `build.started` только при достоверном переходе в строительство |
| Завершение стройки | WS `world.building.updated`, состояние `active` | `build.completed` | `building.Tile` | Владельцу, соседям вблизи | **частично**; сравнить предыдущее состояние, не играть при начальной загрузке; нет причины `new/upgrade/rush` |

| Снос (`Inspector`) | Успех `deleteBuildingRequest`; WS `world.building.removed` | `build.demolished` | Координата выбранной постройки до удаления | Инициатору; рядом другим | **частично**; WS содержит лишь `building_id`, нет координаты и причины удаления |
| Поле: переход стадии / сбор (`Inspector`, `IsoMap`) | Успех `advanceField` / `harvestField` → `building`, `inventory` | `economy.crop.ready` при однозначном переходе; `economy.harvest.field` после сбора | `result.building.tile_x/y` | Владельцу; тихий мир рядом | **есть** для сбора; автоматическая готовность требует сравнения состояния, таймер молчит |
| Производство: запуск / сбор (`ProductionPanel`, `IsoMap`) | Успех `startProduction` / `patchProductionJob` → `job`, `inventory` | `economy.production.started` / `economy.production.collected` | Через известное `job.building_id` | Владельцу | **есть** при ответе; `cancel` не считается сбором |
| Производство: готовность | WS `economy.production.completed` → `job`, `inventory`; также опрос jobs | `economy.production.ready` | Через `job.building_id` и кеш постройки | Владельцу | **частично**; событие есть на сервере, но отсутствует в `WorldEventType` и обработчике `realtime.ts`; опрос при входе не озвучивать |
| Инвентарь, монеты, редкая награда (`ResourceBar`, `useInventory`) | WS `economy.inventory.changed` или GET inventory | `economy.coin.earned/spent`, `economy.reward.rare` | Не нужна | Владельцу | **нет** по одному изменению: нет причины, дельты и ID действия; опрос/вход молчит; брать конкретный успешный ответ |
| Лес, рубка (`IsoMap`) | Успех `chopForest` → `tile`; WS `world.tile.changed` | `world.forest.cut` | `result.tile` | Инициатору; рядом другим только с известной причиной | **частично**; WS не различает рубку и отрастание; собственный звук по API один раз |
| Ресурсный узел: захват / сбор / истощение / возрождение | API `patchResourceNode` → `node`, `inventory`; WS `world.resource.changed` | `economy.node.claimed`, `economy.gather.*`, `economy.node.depleted`, `economy.node.respawned` | `node.tile_x/y` или `node.Tile` | Инициатору; рядом видимому наблюдателю | **частично**; ответ позволяет различить команду, WS содержит состояние без причины; фазу перехода определять по предыдущему состоянию, не по первичной загрузке |
| Ручная атака монстра (`Inspector`) | Успех `attackMonster` → `monster`, `loot`; WS `monster.damaged/died` | `combat.player.attack`, `combat.monster.hit/death` | `monster.tile_x/y` или `monster.Tile` | Инициатору; рядом видимым игрокам | **частично**; не повторять удар из WS после API; WS не указывает источник урона |
| Монстр: движение, агро, удар, смерть, трофей | WS `monster.moved/attacked/died/loot.dropped/loot.claimed` | `combat.monster.aggro/attack/death`, `combat.loot.dropped/claimed` | `monster.Tile`; у loot — `loot.Tile` | Рядом; личное получение трофея — владельцу | **частично**; `aggro` выводится из перехода состояния, `monster.attacked` не содержит дельту HP или тип цели в отдельном поле; не звучать на каждый `moved` |
| Орудие выстрелило | WS `cannon.shot` | `combat.weapon.cannon/tower/bolt_thrower/storm_coil` | Нет в payload; возможно найти `building_id` в кеше | Только владелец сейчас | **частично**; сервер посылает событие с `player_id`, без `chunk_id` и координат; общий звук соседям требует расширения контракта/маршрутизации; `monster.damaged` уже сопровождает выстрел |
| Чат: отправка / получение / упоминание (`ChatPanel`) | Успех `sendChatMessage` → `message`; WS `chat.message.created` | `social.chat.sent/received/mention` | Не нужна | Отправителю / адресатам канала | **частично**; WS тип есть, но панель использует опрос; свои сообщения исключать по `author_id`, упоминание — только после подтверждения сервером либо надёжного разбора, текст не логировать |
| Союз: создание, приглашение, ответ, казна (`AlliancePanel`) | Успех API; WS `alliance.created/invite.created/invite.accepted/invite.declined/treasury.donated` | `social.alliance.invite/accepted/declined/treasury` | Не нужна | Участникам/адресату | **частично**; UI сейчас даёт создать союз и пожертвовать, но не управляет приглашениями; события есть в `shared/events/alliance.ts`, получателей проверять по конверту |
| Рынок: выставить / сделка / отмена (`AlliancePanel`) | Успех `createMarketOrder`; WS `market.order.created/filled/cancelled` | `economy.market.listed/bought/sold/cancelled` | Не нужна | Сторонам ордера | **частично**; UI создаёт ордер, API отмены есть без UI; `filled` нужен для фактической сделки, `created` нельзя озвучивать как продажу |
| Угроза, рейд, победа, территория, руины, склад, уровень | Специальный серверный результат | `combat.threat.*`, `world.*`, `economy.storage.*`, `economy.level.up` | По будущему payload | Адресатам/рядом по типу | **нет** для точного сигнала: текущие общие события не содержат требуемых причин; добавить контракт вместе с механикой |

## Недостающие поля и решения для следующей фазы

1. Добавить `economy.production.completed` в типизированный frontend-конверт и обработчик; сопоставлять `job.building_id` с координатой только из актуального кеша.
2. Для `world.building.updated/removed` передавать причину (`construction`, `upgrade`, `rush`, `combat`, `demolition`), прежнее состояние/HP или подтверждённую дельту, координату удаления и идентификатор действия. До этого не выбирать по WS звук урона, апгрейда или сноса по догадке.
3. Для `world.tile.changed` и `world.resource.changed` передавать причину и исполнителя. Изменение состояния без предыдущего снимка не доказывает действие игрока.
4. Для `monster.attacked/damaged/died` и `cannon.shot` передавать источник, цель, координату, фактический урон и связь событий одного удара. Сейчас `cannon.shot` приватен владельцу и не содержит координаты.
5. Для экономических наград использовать ответ конкретной mutation либо добавить причину/дельту/`action_id` к персональному событию. `economy.inventory.changed` остаётся сигналом обновления кеша.
6. Сохранить `event_id`, `seq`, `payload_version`, `player_id` и `alliance_channel` из `RealtimeEnvelope`; фильтровать адресата и повторы до выбора звука. Повтор ответа API и WS сопоставлять по ID действия, когда он появится.
