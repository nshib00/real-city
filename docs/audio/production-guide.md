# Производство звуков в Linux и WSL

## Среда

Проверено 24 октября 2026 года: `python3` — 3.13.5; `ffmpeg`, `sox` и `audacity` в текущем WSL не найдены. Генератор WAV работает без них. Для полной сборки на Debian/Ubuntu установить `ffmpeg`, `sox`, `audacity` штатным пакетным менеджером в среде с правами администратора:

```bash
sudo apt update
sudo apt install ffmpeg sox audacity
ffmpeg -version
sox --version
audacity --version
ffmpeg -encoders | rg libmp3lame
```

В текущем контейнере `sudo` заблокирован режимом `no new privileges`. Для проверочной сборки установлен локально в `.cache/audio-deps` пакет `imageio-ffmpeg` 0.6.0 с FFmpeg 7.0.2-static и `libmp3lame`; путь передаётся через `--ffmpeg`. Кеш исключён из Git и не является зависимостью проекта. SoX и Audacity остаются недоступными в контейнере; Audacity можно запускать на Windows, но исходные записи должны быть доступны WSL по пути к файлу.

## Синтез и сборка

После добавления игрового события выбрать подтверждённый API/WS-источник в `event-matrix.md`, объявить `sound_id` в `frontend/src/audio/soundEvents.ts`, создать рецепт в `tools/audio/recipes/` и записать происхождение в `asset-register.md`. Собрать WAV и MP3, затем проверить `python3 tools/audio/validate_audio.py --catalog`, `cd frontend && npm test -- --run src/audio && npm run assets:budget`. В клиенте `soundCatalog.ts` назначает шину, приоритет, громкость, лимит голосов, cooldown и preload; исключения задавать в `soundEventOverrides`. Для подтверждённых действий писать тест на источник звука и на отсутствие дубля от WS.

Клиент создаёт `AudioContext` после первого жеста через `AudioProvider`, декодирует MP3 лениво и хранит до 16 МБ PCM в памяти. Шины `master/ui/world/alerts/ambience` управляются в панели «Звук». Атмосферные петли работают через Web Audio и плавно меняют громкость. Ошибка MP3 переключает на другой вариант; если все варианты недоступны, действие остаётся без звука. Для просмотра состояния в dev-режиме открыть `?assets`: панель показывает контекст, голоса, кеш, последний `sound_id`, ограничения и ошибки. Стыки петель и их баланс на разных устройствах ещё требуют ручного прослушивания.

Из корня репозитория:

```bash
python3 tools/audio/generate_sfx.py ui.click --candidate a --variant 0
python3 tools/audio/validate_audio.py tools/audio/master/ui.click.a.0.wav
python3 tools/audio/build_audio.py ui.click
python3 tools/audio/build_audio.py --all
```

Рецепт задаёт seed, слои, ADSR, частотный сдвиг, фильтр, отражение и 2–3 варианта. Результат генератора — mono PCM16 48 кГц с пиковым уровнем около −3 dBFS. Сборка применяет FFmpeg-фильтры `highpass=f=35`, короткий `afade` на входе и выходе, мягкий `acompressor` (порог 0.35, соотношение 1.5:1) и `alimiter=limit=0.7079:level=0`; затем проверяет WAV: 48 кГц, mono PCM16, длительность 30 мс–2 с, пик не выше −2.5 dBFS. Кодирование: `libmp3lame`, 64 кбит/с, mono, 48 кГц. MP3 лежит в `frontend/public/assets/audio/<семейство>/`, пути вариантов — в `soundManifest.ts`. Параметры FFmpeg зафиксированы в `build_audio.py`; изменять их следует вместе с повторной громкостной приёмкой.

MP3 содержит задержку кодека, поэтому длительность эффекта оценивается по master WAV. Проверка бюджета: `cd frontend && npm run assets:budget`. Перед выпуском прослушать результат в браузере и проверить кодирование декодером FFmpeg/браузера.

Если системный FFmpeg недоступен, передать путь к локальному исполняемому файлу через `--ffmpeg`, например `.cache/audio-deps/imageio_ffmpeg/binaries/ffmpeg-linux-x86_64-v7.0.2` в текущем окружении. Для предварительной проверки синтеза без FFmpeg существует `--wav-only`: он создаёт PCM WAV и временно записывает их в manifest; для релиза после этого нужно пересобрать те же ID в MP3. Для многочисленных вариантов монстров использовать `--bitrate 32k`; обычный режим кодирует 64 кбит/с. Бюджет 150 КБ проверяется для смыслового подсемейства по первым двум частям `sound_id` (`economy.gather`, `combat.monster`), общий бюджет каталога — 5 МБ.

Фаза 6 добавляет `world.*`, `social.*` и `ambience.*` из одноимённых рецептов. Атмосферные файлы собраны mono 48 кГц, 32 кбит/с, по одной петле на ID. Атмосфера отдельно включается кнопкой в панели инструментов, по умолчанию молчит, а клиент одновременно держит до двух биомных и двух локальных петель. Их баланс, качество стыка и работа на телефоне требуют ручного прослушивания в фазе 8. Звуки `world.ruin.captured`, `world.territory.claimed` и `world.resource.discovered` зарегистрированы, но ждут соответствующих серверных результатов; воспроизведение при простой загрузке карты запрещено.

## Записанный Foley

Для хлопка по дереву, зерна в миске, монет/металла, камешков и бумаги/ткани записать короткую серию в тихой комнате, без автоматической регулировки усиления по возможности. Сохранить необработанный WAV в `tools/audio/recordings/` и внести дату, автора, оборудование/условия и путь в [реестр](asset-register.md). Сторонние сэмплы без права переработки и распространения не использовать.

В Audacity выбрать удачный дубль, убрать постоянный шум по чистому участку, удалить щелчки и тишину, оставить хвост, экспортировать WAV PCM. Не агрессивно давить шум: артефакты заметнее тихой комнаты. Затем выполнить:

```bash
python3 tools/audio/build_audio.py ui.click --recording ui.click=tools/audio/recordings/wood_tap.wav
```

Скрипт ресемплирует и приводит запись к mono, применяет ту же очистку/fades/лимит, создаёт варианты с небольшим сдвигом высоты, проверяет WAV и кодирует MP3. При отсутствии записи исходный синтез остаётся воспроизводимым запасным вариантом. Для новой записи перед сборкой проверить её длительность и отсутствие клиппинга вручную.

Путь `--recording` проверен на WAV-заглушке через локальный FFmpeg; реальных Foley-записей пока нет. После проверки тестового ввода каталог снова собран из синтезированных рецептов.
