# Выпуск и откат звукового каталога

`frontend/src/audio/soundManifest.ts` содержит пути MP3 с `?v=<первые 12 символов SHA-256>`. `tools/audio/build_audio.py` добавляет версию при сборке звука; `tools/audio/version_manifest.py` обновляет версии существующих MP3 без перекодирования. Клиент и manifest выпускать вместе. Статические MP3 можно кешировать долго при условии, что CDN учитывает query string в ключе кеша. Если CDN игнорирует его, настроить ключ кеша или использовать короткий TTL для `/assets/audio/`.

Перед выкладкой выполнить `python3 tools/audio/validate_audio.py --catalog`, `cd frontend && npm run lint && npm test && npm run build && npm run assets:budget`. Валидатор проверяет, что версия ссылки соответствует содержимому файла. Не запускать генератор звука при старте сервера или браузера.

При ошибке каталога вернуть предыдущую сборку клиента вместе с предыдущими `soundManifest.ts` и MP3. После отката проверить один UI-сигнал, один мировой сигнал и mute. Не удалять старые MP3 из CDN до истечения времени кеширования старого клиента. Если один MP3 пропал, движок пробует другой вариант того же `sound_id`; если вариантов нет, он молчит и пишет агрегируемую локальную ошибку в dev-панель.
