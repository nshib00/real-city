# Включение и возврат оформления интерфейса

## Доступное переключение

В игровой панели «Ответ сервера и эффекты» выбрать «Оформление → Эолия». Вернуть прежние материалы: «Классическое». По умолчанию остаётся классическое оформление. Настройка хранится в `real-city.interface-theme`; при запрете localStorage переключение действует до перезагрузки. Она относится к устройству, не содержит игровых или персональных данных.

Переключение меняет CSS-переменные и атрибут корневого элемента. React-дерево, Pixi canvas, выбор, формы, таймеры и сетевые команды от него не пересоздаются. Смена аккаунта, напротив, перемонтирует игровую поверхность для очистки локального контекста. Изменений БД и серверного баланса нет. Классическое оформление возвращает материалы панелей; исправления доступности, чата и загрузки графики действуют в обоих вариантах.

## Значение для нового устройства

Для сборки можно задать `VITE_INTERFACE_THEME_DEFAULT=aeolian` или `classic`. Значение применяется только когда на устройстве ещё нет сохранённого выбора; сохранённая настройка игрока имеет приоритет. Любое неизвестное значение безопасно сводится к `classic`. Переменная Vite встраивается в клиентскую сборку и не является секретом или процентным распределителем аудитории. Чтобы начать rollout выбранной группе, используйте отдельное окружение/релиз и процедуру назначения аудитории платформы; для отката верните окружение на `classic` и предыдущий пакет фронтенда.

## Этапы включения

Тема уже поставляется в клиенте, но production по умолчанию остаётся классическим до прохождения внешней приёмки. Проверять и выпускать её следует последовательно:

1. Токены и поверхности: сверить палитру, контраст, фокус и карту на desktop/mobile.
2. HUD: проверить строку ресурсов, инструменты и статус соединения, не меняя игровые запросы.
3. Контекстные панели: проверить инспектор, строительство, профиль, союз, производство, журнал и чат.
4. UI-ассеты: проверить иконки, fallback загрузки, бюджеты и снимки на DPR 1/2.

На каждом этапе начинать с внутреннего стенда, затем проверять изолированный браузерный CI и живой игровой цикл на тестовом сервере. После этого можно включать тему для выбранной группы игроков средствами rollout-конфигурации окружения/релиза. Клиентская настройка темы сама по себе не является процентным feature flag и не задаёт группу пользователей. Не удалять переключатель, пока не приняты все этапы и не завершён период наблюдения.

При регрессии вернуть «Классическое» в настройке устройства. Для срочного отката релиза отключить новый пакет фронтенда/вернуть предыдущую версию фронтенда; сервер, БД и миграции не трогать. После отката убедиться, что клиент снова загружает предыдущий `index.html` и связанные assets из одной версии.

## Проверка перед включением по умолчанию

1. Выполнить `cd frontend && npm run lint && npm test && npm run build`.
2. Запустить `node node_modules/playwright/cli.js test -c playwright.rollout.config.ts`; сценарий использует настоящий React/Pixi и изолированный API fixture, сохраняет обе темы на шести размерах. Это не проверка живого сервера.
3. Выполнить существующие `playwright.review.config.ts` и `playwright.interface.config.ts`, просмотреть снимки, перекрытия, контраст и 200% текст. Координатный выбор не должен рубить лес или отправлять атаку.
4. В CI `real-gameplay.spec.ts` на настоящем API/WS переключает обе темы после входа, проверяет сохранность canvas и отсутствие mutation-запросов от переключения, затем выполняет строительство и сбор ресурсов. На поднятом тестовом сервере дополнительно пройти конкурентный отказ, ремонт, бой, удаление выбранной цели и смену аккаунта. Во время незавершённого действия переключить тему и вернуть её: запрос должен остаться единственным.
5. На реальном телефоне и планшете проверить жесты двумя пальцами, safe-area, экранную клавиатуру и обе ориентации. Скринридером проверить карту → координаты → инспектор → действие; объявления тиков недопустимы.
6. Снять сравнимые FPS, задержку управления, память и площадь доступной карты на одном устройстве/сцене до и после. Проверить отключённые эффекты и звук. Записать фактические результаты и ограничения в отчёт очереди.

Включение новой темы по умолчанию в действующем production пока не выполнено. Значение для новых устройств уже настраивается при сборке, но само назначение аудитории, независимое ревью визуальных дифов, физическое устройство/скринридер и парный production/mobile профиль остаются открытыми. Публикация в действующий production в эту работу не входит.

## Ошибки графики

Загрузка PNG карты делает не более трёх автоматических попыток на URL с паузами между повторными перерисовками. После исчерпания попыток остаётся упрощённая геометрия и кнопка «Повторить загрузку графики»: она начинает новый ограниченный цикл. Статус сообщает количество загрузок; ошибки поступают в существующую локальную телеметрию без URL. Пользовательский повтор не меняет мир и не повторяет игровые действия.

Версия в URL отделяет состояние загрузки разных PNG. Это не доказывает корректность версионирования изображения, указанного внутри atlas JSON. Управляемое освобождение всех GPU-текстур и упаковка всех семейств ещё не завершены; без измерений нельзя заявлять ограниченное потребление памяти.
