# Диагностика клиентских сбоев

Клиент регистрирует только фиксированные сигналы: runtime, необработанный Promise, ассет, render, граница ошибки React, неудачное действие, открытие меню строительства/реестра ресурсов/панели союза, переподключение WS, восстановление WS и пропуск последовательности. Текст исключения, URL, токены, содержимое чата, ID игрока и координаты не передаются. Поля отчёта: schema=1, версия package.json, сигнал, минута UTC от epoch. События панели срабатывают только при открытии; частые действия игрока не записываются.

Приёмник пока локальный: событие окна `real-city:client-telemetry`, `detail` содержит массив отчётов. Это диагностический канал, а не централизованный мониторинг. Можно подписаться через DevTools до воспроизведения сбоя; подписчик не должен выбрасывать исключения. Без подписчика отчёты после отправки не сохраняются. Серверного endpoint и удалённого хранилища в этой итерации нет.

Один вид сигнала попадает в очередь не чаще раза в минуту. Очередь — до 32 записей, отправка раз в 30 секунд и при online; offline удерживает ограниченную очередь. Ошибка приёмника не вызывает новую телеметрию и немедленный повтор. Смена аккаунта очищает очередь и окно дедупликации; завершение старой неуспешной отправки не возвращает данные в новую очередь. Данные не сохраняются в localStorage. Текущий приёмник локальный и не даёт эксплуатационных метрик до подключения аутентифицированного серверного sink.

## Пустая карта

1. Проверить наличие `render_error`, `runtime_error`, `asset_error`, затем состояние WebGL и вкладку Network. Не копировать URL с query-параметрами авторизации в обращения.
2. Проверить успешность запросов видимых чанков, построек, ресурсов и монстров. Ответы HTTP и WS проверять на одной версии клиента и сервера.
3. При `ws_gap` или `ws_recovered` проверить повторное чтение активных запросов. Наличие сигнала само по себе не подтверждает успешный resync.
4. Сопоставить минуту и версию с закрытыми серверными логами без добавления ID игрока в метки метрик.

## Ошибки ассетов

Проверить HTTP-статус, Content-Type, актуальность manifest и cache-control для хэшированных файлов. Сверить `npm run assets:budget` и аудиовалидатор. Сначала устранить несовпадение версии HTML/manifest/файлов; очистку браузерного кэша использовать как диагностический опыт, а не постоянное исправление.

## Удалённый сбор

Перед подключением нужны серверный приёмник с лимитом тела и частоты, фиксированная схема, ограниченная retention, интеграционные тесты отказа/восстановления и метрики потерь. Локальное DOM-событие не даёт эксплуатационных оповещений и не закрывает пункты 55–56.
