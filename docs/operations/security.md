# Безопасность текущего production-контура

## Запросы и домен

Caddy завершает TLS и направляет `/api/*` в закрытую сеть Compose. `/metrics` и `/debug/*` снаружи возвращают 404. Лимит тела API — 1 МБ. Proxy ждёт соединения с API до 5 секунд и заголовки ответа до 20 секунд. Эти ограничения не заменяют лимиты времени в самом API.

Production API принимает запросы с заголовком `Origin` только от `https://DOMAIN`; иной origin получает 403 до выполнения обработчика, включая preflight и попытку WebSocket handshake. Запрос без `Origin` допускается для CLI и серверных клиентов. Проверка origin не является проверкой личности: для приватных маршрутов требуется действующий access token, а административные операции дополнительно проверяют активную роль администратора в сервисе.

## Токены

API выдаёт короткий access JWT (по умолчанию 15 минут) и refresh token (по умолчанию 30 дней). Клиент хранит оба в `localStorage`; cookie-сессий сейчас нет. Поэтому `HttpOnly`/`SameSite` к ним не применяются, а выполнение чужого JavaScript в origin игры может раскрыть токены. Для этого важны контроль зависимостей, защита от XSS и отсутствие посторонних скриптов в игре. Токен для WebSocket сейчас передаётся в query string; не публикуйте полные URL запросов с ним в логах proxy и диагностических артефактах. Смена этой схемы потребует согласованного изменения клиента и сервера.

Секрет `SESSION_SECRET` хранится вне репозитория и должен быть не короче 32 случайных символов. Смена секрета сбрасывает действительность ранее выданных JWT. При подозрении на компрометацию токена следует завершить сессии пользователя; при компрометации секрета — заменить секрет и завершить все сессии.

## Администрирование

Маршруты `/api/v1/admin/*` доступны через публичный API, но требуют access token и активной роли администратора; действия изменения аккаунтов и модерации проверяются внутри admin service и записываются в аудит. Доступность этих путей через Caddy сама по себе не означает право на действие. Перед внешним выпуском следует вручную проверить отрицательные сценарии для обычного пользователя на целевом домене и правила хранения audit-логов.
