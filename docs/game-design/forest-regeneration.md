# Регенерация леса

## Цель

Лес должен постепенно возвращаться после вырубки, но не должен мешать уже занятой территории игрока. Регенерация работает как мягкое восстановление природного баланса: вырубленная клетка освобождается, а новый лес появляется рядом на подходящей свободной клетке луга.

## Базовые правила

- Регенерация запускается только после полной вырубки лесной клетки, когда `forest_density` падает до `0`, а terrain клетки становится `grass`.
- Новый лес появляется через случайную задержку от `3` до `5` минут после полной вырубки.
- Кандидаты выбираются в квадрате радиуса `4` клетки от срубленной клетки.
- Лес может заменять только terrain `grass`.
- Лес не может появиться на `water`, `mountain`, `ruins`, `oil_well`, `road` и других не-луговых terrain.
- Лес не может появиться на клетке, занятой активной, строящейся, запланированной или поврежденной постройкой.
- Разрушенные постройки сейчас не считаются блокирующими для регенерации, как и в текущей логике placement.
- Если подходящей свободной клетки луга рядом нет, действие считается выполненным без появления нового леса.

## Покрытие лесом

Для локальной зоны вокруг вырубки задан целевой минимум: `30%` свободных природных клеток должны оставаться лесом.

Свободными природными клетками считаются клетки в зоне регенерации, которые:

- не заняты постройками;
- имеют terrain `grass` или `forest`.

Алгоритм не делает тяжелый глобальный пересчет всей карты на каждом тике. Вместо этого он поддерживает покрытие событийно: каждая полностью вырубленная клетка планирует одно восстановление рядом. Это сохраняет плотность леса в активных областях без постоянного обхода большой карты.

## Алгоритм

1. Игрок рубит лес через `ForestService.Chop`.
2. Если после рубки клетка все еще имеет `forest_density > 0`, регенерация не планируется.
3. Если клетка полностью очищена и стала `grass`, создается `game_action` типа `regrow_forest`.
4. `due_at` действия выбирается в диапазоне `3-5` минут от момента вырубки.
5. Simulation runner забирает действие после наступления `due_at`.
6. На момент исполнения сервис повторно загружает чанки вокруг исходной клетки из актуального хранилища, минуя локальный кэш worker. Это важно: за время ожидания другой процесс мог изменить terrain, а игрок — построить рядом здание.
7. Сервис строит карту занятых клеток по постройкам в затронутых чанках.
8. Из всех клеток в квадрате радиуса `4` выбираются только свободные клетки `grass`.
9. Исходная вырубленная клетка не используется как основной кандидат, чтобы вырубка реально освобождала конкретную клетку, а лес восстанавливался рядом.
10. Кандидаты оцениваются по близости к исходной клетке, соседству с существующим лесом и отсутствию построек рядом.
11. Победившая клетка меняется на `forest` с `forest_density = 3`.
12. Публикуется событие `world.tile.changed`, чтобы клиент сразу обновил карту.

## Почему через `game_actions`

Регенерация реализована через существующую очередь `game_actions`, а не через таймер в памяти процесса.

Это дает несколько преимуществ:

- действие переживает рестарт API/worker;
- задержка одинаково работает в memory и Postgres режимах;
- обработка идет тем же simulation runner, что завершение стройки, производство и респаун ресурсов;
- действие можно безопасно повторить при временной ошибке, потому что выбор клетки выполняется заново на момент исполнения.

## Текущие параметры

| Параметр | Значение |
| --- | ---: |
| Минимальная задержка | 3 минуты |
| Максимальная задержка | 5 минут |
| Радиус зоны | 4 клетки |
| Целевое локальное покрытие лесом | 30% |
| Плотность нового леса | 3 |

## Ограничения текущей версии

- Нет отдельного глобального фонового процесса, который восстанавливает лес в давно обезлесенных областях без новых рубок.
- Регенерация не создает лес на исходной клетке, если рядом есть другой свободный луг.
- Если вокруг вырубки все клетки заняты или не являются лугом, лес не восстанавливается для этого действия.
- Алгоритм поддерживает локальную плотность леса вокруг активной вырубки, но не пересчитывает процент леса по всей карте.
