# Версии игрового баланса

Текущая версия сохранённого мира и данных — **2**. `data/buildings/catalog-v2.json` задаёт 72 типа построек: ID, русское имя, доступность прямого размещения, размер, цену, строителей, HP, время и уровни. У всех типов теперь указан явный положительный HP; прежние 17 отсутствующих значений фактически означали 100 HP, поэтому заполнение не меняет уже действовавшее здоровье. `python3 tools/buildings/generate_catalog.py` обновляет `shared/catalog/buildings.ts` и встроенную копию Go. В API `GET /api/v1/buildings/catalog?scope=all` доступны все 72 типа со всеми уровнями; запрос без `scope=all` остаётся меню прямого строительства.

`data/balance/v2.json` задаёт ресурсы, рецепты каждого уровня, расход бензина на цикл, редкие выходы, параметры монстров, оружия игроков и оборонительных установок, стоимость/время/HP восстановления 12 руин и базовые правила атаки. Длительности в этом JSON измеряются **наносекундами Go `time.Duration`**, а поля `pvp.*_seconds` — секундами. Рабочей механики энергии пока нет; бензин (`fuel`) расходуется в рецептах через `FuelPerRun`. Встроенная копия расположена в `backend/internal/domain/catalog/balance.v2.json`. Go валидирует версии, полноту записей, уникальность ID, ссылки на ресурсы и допустимость чисел до старта сервера. Старые Go-таблицы пока сохранены как исходный материал для экспортера; игровые чтения используют снимок.

Проверки: `make catalog-check`, `make backend-test`, `cd frontend && npm run lint`. Первая команда сравнивает копии JSON, сверяет data/shared/Go и таблицы в 72 документах `docs/buildings`, затем запускает тест декодирования снимка. Скрипт `python3 docs/buildings/sync-runtime-tables.py --write` обновляет действующие числовые таблицы документов. Художественные и ещё не принятые варианты в старом тексте документов не переопределяют игровой каталог.

Миграция `000034_balance_version.sql` создаёт `game_balance_version`, а `000038_building_balance_v2.sql` переводит сохранённый мир на версию 2: сохраняет долю HP старых вилл и многоквартирных домов, переносит старые многоквартирные дома на уровень 1 и затем обновляет версию. Backend останавливает запуск, если версия сохранённого мира не равна `catalog.BalanceVersion`; таким образом новый баланс не применяется к старой БД без миграции. Для обратного перехода на версию 1 нужна резервная копия мира: автоматический откат остановлен, поскольку в версии 2 появляются новые уровни построек.

Для следующей версии баланса нужно:

1. Зафиксировать изменения в новых `catalog-v3.json` и `balance/v3.json`, обновить Go/TS-копии и `BalanceVersion`.
2. Написать миграцию сохранённого мира **до** изменения версии в БД: для изменённого максимального HP сохранить долю здоровья (`new_hp = round(old_hp * new_max / old_max)`), отдельно обработать разрушенные объекты, незавершённую стройку, производство и назначенные действия. Уже списанные ресурсы задним числом не корректировать.
3. В той же миграции обновить `game_balance_version` до 3. Проверить её на копии мира версии 2 с активными и повреждёнными зданиями, заданиями и владельцами клеток; проверить запуск backend, инвентари и API smoke.
4. Для отката подготовить обратную миграцию данных или резервную копию. Возврат только JSON-файла без отката сохранённого мира запрещён проверкой версии.

`backend/cmd/balance-export` служит для первичного экспорта текущего Go-баланса; после перехода на JSON он читает уже загруженный снимок. Для очередной версии правят канонический JSON и проверяют встроенную копию, а не используют экспорт как источник новых чисел.
