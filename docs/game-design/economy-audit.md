# Аудит экономики Real City

Исходный аудит: 6 октября 2026. Сверка предметных конфликтов: 24 октября 2026.

## Актуальные решения по идентификаторам и расхождениям

Этот раздел имеет приоритет над историческим снимком ниже. Текущий shared-каталог содержит **77 ресурсных ID**; отсутствовавший в серверном списке характеристик `super_mechanism` добавлен в `backend/internal/domain/catalog/economy.go`. `tools` и `aeolian_alloy` также существуют в обоих словарях. Наличие ID не доказывает доступность добычи или рецепта.

| Конфликт | Принятое правило | Что ещё требуется в игре |
| --- | --- | --- |
| Нефть и растительное масло | `oil` — ископаемая нефть из скважины/узла, расходуется нефтепереработкой; `plant_oil` — пищевое/техническое растительное масло из маслобойни. Не смешивать инвентарь, рецепты и русские подписи. | Проверить, что все рецепты маслобойни выдают `plant_oil`, а нефтяная цепочка использует `oil` и `fuel`. |
| Эолиевый сплав | Единственный ID — `aeolian_alloy`; он уже есть в backend и shared. Упоминания «эолиевый сплав» без ID в старых документах ссылаются на него. | Подтвердить производственный рецепт и доступность ингредиентов до требования сплава в ценах. |
| Инструменты | Единственный ID — `tools`; он уже есть в обоих словарях и ценах зданий. Старое утверждение «ресурс не существует» более не действует. | Проверить рабочий рецепт и ранний источник до первого обязательного апгрейда с `tools`. |
| Железо и слитки | `iron_ore` — руда; `iron` — металлургический полуфабрикат для стали; `iron_ingot` — строительная заготовка для цен. Эти ID не являются синонимами и не конвертируются автоматически. | В рецептах явно указать переходы `iron_ore` → `iron` / `iron_ingot`; подтвердить источники обоих выходов. |
| `influence_seal` | Оставить как зарезервированный дизайн-концепт. Shared-only запись и статические подписи удалены; в активной цене, награде и UI игрового инвентаря ID не используется. Контролируемая территория исключена из актуального плана. | Возвращать ID только вместе с серверной механикой руин, источником ресурса и тестами контрактов. |
| Названия постройки и ID | Каноничен `building_id` из backend/shared; русское имя и имя файла — подпись/алиас. `standard_road` — «Обычная дорога» (`common-road.md`), `road` — «Грунтовая дорога», `field_bed` — «Грядка ветролиста», `lumber_yard` — «Лесопильный двор». | Проверять поиск по ID, а не по русскому заголовку; соответствия записаны в [реестре построек](../buildings/catalog-coverage.md). |
| Разные цены и проектные уровни | Для доступной постройки фактические серверные уровни, цены и ограничения определяет backend-каталог; shared и документация должны ему соответствовать. Проектные уровни отделяются пометкой «проект» и не обещаются в UI. | Пройти по всем строкам реестра в пункте 21.12; исправлять расхождения вместе с контрактом и миграцией, не одной правкой текста. |
| Супер-волокно и супер-ветролист | `super-windleaf` остаётся редким урожаем ветролиста; `super-fiber` относится только к волокнистым культурам и не заменяет его. | Подтвердить источник `super-fiber` перед использованием в рецептах. |

Исторические таблицы ниже фиксируют состояние на 6 октября. Их числа и рекомендации не применять к текущему каталогу без повторной сверки. Доступность ресурсной цепочки остаётся отдельной проблемой даже при наличии ID.

## Текущая контрольная проверка 24 октября 2026 года

- `python3 docs/buildings/audit-catalogs.py`: **73/73** типа и все игровые уровни совпадают по ID, русскому имени, категории, размеру, переходам апгрейда, времени, строителям, HP и цене между shared и backend. Обнаруженные отсутствовавшие переходы `apartment_house` → `residential_skyscraper` и `villa` → `palace` добавлены на сервере. Frontend получает generated shared-каталог, API отдаёт backend-каталог из того же data-файла.
- `python3 docs/buildings/check-coverage.py`: **73** текстовые и **73** визуальные спеки; **77** ресурсных ID, ошибок ссылок, уровней и отрицательных цен нет. Наличие спеки не доказывает доступность ресурса в мире.
- `python3 tools/buildings/check_balance_snapshot.py`: версионированный снимок каталога v1 совпадает с shared-каталогом; Go-тест дополнительно сравнивает все уровни с runtime backend. Порядок обновления сохранённого мира описан в [правилах версий баланса](balance-versioning.md).
- Из `backend/internal/domain/catalog/economy.go` удалён второй экземпляр `super-fiber`; тест `TestResourceCatalogHasUniqueTypes` проверяет уникальность публичного списка ресурсов.
- В категории industry остаются объекты без серверного производственного рецепта: `brick_kiln`, `forge`, `dye_works`, `optical_workshop`, `mint`, `mine`, `iron_mine`, `rope_yard`, `chemical_workshop`, `precision_workshop`. Их роль в индивидуальных документах помечена как проектная; строить цепочку поздней экономики через эти выходы пока нельзя.
- Общие тесты backend-каталога и сервисов проходят, но сквозной сценарий «новый игрок → добыча → промышленность → поздние цены → восстановление после разрушения» не подтверждён. До закрытия этого сценария пункт 21.15 плана остаётся в работе.

Следующая сверка 21.12 должна разобрать старые таблицы с пометкой «проектный баланс» по каждому уровню: либо обновить документ по действующему каталогу, либо согласовать изменение баланса в обеих реализациях и миграцию сохранённого мира. Текущий аудит shared/backend не делает проектную таблицу игровой автоматически.

Этот документ заменяет устаревший раздел аудита из `docs/game-design/resources-list.md`, но не перезаписывает сам файл со списком идей ресурсов. Проверка сделана по текущему состоянию проекта:

- `backend/internal/domain/economy/economy.go` - серверные типы ресурсов, стартовый инвентарь и лимиты.
- `backend/internal/domain/catalog/economy.go` - публичный backend-каталог ресурсов и рецепты производства.
- `backend/internal/domain/catalog/buildings.go` - серверные цены зданий и апгрейдов.
- `shared/catalog/resources.ts` и `shared/catalog/buildings.ts` - shared-каталоги для UI.
- `backend/internal/service/forest.go`, `backend/internal/service/field.go`, `backend/internal/service/resource.go`, `backend/internal/service/production.go` - реальные интерактивные источники ресурсов.
- `backend/internal/adapter/memory/economy_repo.go` и `backend/internal/adapter/postgres/economy_repo.go` - dev-узлы ресурсов и постоянное хранение.
- `frontend/src/features/hud/ResourceBar.tsx` и `frontend/src/features/resources/ResourceRegistry.tsx` - видимость ресурсов в интерфейсе.

## Краткий вывод

Экономика уже выросла из раннего прототипа: в backend определен 51 ресурс, в shared-каталоге - 52 ресурса, а цены зданий используют 39-45 разных ресурсов в зависимости от каталога. При этом реально замкнуты только ранние цепочки: вырубка леса, грядка ветролиста, песчаный карьер, стекольная мастерская, лесопилка, каменотесы, кирпич, нефтяные узлы и бензин.

Главная проблема - каталог цен опережает игровую добычу. Многие ресурсы уже используются в стоимости апгрейдов, но не имеют рецепта, добывающего здания, узла или события. Стартовый инвентарь теперь выдает только `50` монет и больше не закрывает сырьевые разрывы, поэтому самые критичные блокеры: `tools`, `rope`, `copper_parts`, `iron_ingot`, `mechanism`, `premium_planks`, `reinforced_concrete`, `reinforced_beams`, `armor_plates`, `gold_ingot`, `super_mechanism`, `emerald_dust`, а также сырье `wood`, `stone`, `clay`, `coal`, `iron_ore`, `copper`, `flax`, `herbs`, `mushrooms`, `seeds`.

## Частично реализованные, но не замкнутые ресурсы

| Ресурс | Текущее состояние | Что мешает цепочке |
| --- | --- | --- |
| `coins` | Новый игрок получает `50` монет; далее монеты дают вырубка леса, грядка ветролиста, песчаный карьер, лимит через хранилища монет. | Стартовых 50 монет не хватает даже на большинство первых построек, поэтому нужен ранний сценарий добычи/заработка до строительства. |
| `population` | Есть как ресурс и как стоимость рабочих; жилье увеличивает население через здания. | Это системный показатель, а не добываемый ресурс. Нужно строго отделять свободных рабочих от общего лимита жителей. |
| `wood` | Есть лес и memory-узел, но стартового дерева больше нет. | Production-цепочки требуют большие объемы дерева; нужна серверная генерация лесных узлов или понятный баланс вырубки. |
| `stone` | Есть memory-узел, но стартового камня больше нет. | Нет полноценной добычи через шахту/карьер на постоянной карте. |
| `oil` | Есть memory-узлы и нефтяной terrain, но стартовой нефти больше нет. | Нефтяные тайлы пока не превращаются автоматически в resource nodes или добывающие здания. |
| `sand` | Есть песчаный карьер, но стартового песка больше нет. | Цепочка рабочая, но карьер не привязан к песчаным/водным тайлам и требует ресурсов на постройку. |
| `blue_salt` | Есть редкий выход песчаного карьера. | Используется в поздних апгрейдах карьера; цепочка есть, но редкость нужно проверить симуляцией темпа. |
| `glass` | Есть стекольная мастерская, но стартового стекла больше нет. | После первых уровней зависит от `coal`, затем от `fuel`; топливо и уголь на старте отсутствуют. |
| `star_glass` | Редкий выход стекольной мастерской с 3 уровня. | Используется в апгрейдах стекольной мастерской, но шанс низкий и нет альтернативного источника. |
| `light_crystal` | Редкий выход стекольной мастерской с 5 уровня, на старте отсутствует. | Требуется в поздних апгрейдах, но источник сверхредкий и поздний. |
| `brick` | Рецепт есть. | Завязан на `clay` и `coal`, у которых нет возобновляемой добычи. |
| `stone_block` | Рецепт есть. | Завязан на `stone`, а постоянная добыча камня не замкнута. |
| `planks` | Рецепт есть. | Завязан на `wood`; поздние уровни требуют `fuel`. |
| `elderwood-heart` | Редкий drop леса. | Есть источник, но нет понятной роли в ценах текущих зданий. |

| `super-fiber` и `super-windleaf` | Оба есть, но текущая грядка производит только `super-windleaf`. | Решить, нужен ли `super-fiber`; если нужен, привязать к льну/волокну, не к ветролисту. |
| `sulfur` | В каталоге отмечен как crafted, но по смыслу это сырье или полуфабрикат. | Перенести в raw или clearly описать как продукт химической мастерской. |

## Приоритет исправлений

1. Синхронизировать словари ресурсов:
   - добавить `tools` во все каталоги или убрать его из цен;
   - решить судьбу `influence_seal`;
   - явно развести `iron`/`iron_ingot` и `super-fiber`/`super-windleaf`.

2. Замкнуть раннюю экономику:
   - глина через глиняный карьер;
   - уголь через шахту или coal node;
   - камень через шахту/карьер вместо одного memory-узла;
   - лен, травы, грибы и семена через отдельные поля.

3. Замкнуть первый промышленный слой:
   - `rope` из льна/ветролиста;
   - `fabric` из льна/ветролиста;
   - `tools` из дерева/железа;
   - `iron`/`iron_ingot` из `iron_ore` + `coal`;
   - `copper_parts` из `copper` + металла.

4. Замкнуть средний слой:
   - `mechanism`;
   - `cement`, `concrete`, `reinforced_concrete`;
   - `steel`;
   - `premium_planks` как редкий или поздний выход лесопилки.

5. Замкнуть поздний слой:
   - `reinforced_beams`, `armor_plates`, `electronics`, `super_mechanism`;
   - `gold_ingot`, `rune_tile`, `emerald_dust`;
   - альтернативные источники `light_crystal`, чтобы поздние цены не зависели только от сверхредкого выхода стекольной мастерской.

6. Наполнить persistent world ресурсными узлами:
   - добавить seed/генерацию `resource_nodes` для Postgres;
   - связать oil terrain с нефтяными узлами или зданием нефтяной скважины;
   - добавить типы узлов для камня, глины, угля, железа, меди и серы;
   - проверить respawn и ownership для спорных ресурсов.

7. Обновить UI после серверных решений:
   - top bar оставить коротким, но registry должен показывать только серверно известные ресурсы;
   - production panel должен показывать редкий выход и fuel cost понятнее;
   - build menu должен предупреждать о ресурсах, которые еще нельзя получить в игре.

## Минимальный следующий пакет работ

Самый короткий путь к играбельной экономике без больших переделок:

1. Добавить `tools` как ресурс и рецепт `tools_from_iron`.
2. Добавить рецепты:
   - `rope_from_flax` в `weaving_yard` или `rope_yard`;
   - `fabric_from_flax` в `weaving_yard`;
   - `iron_ingot_from_ore` в `forge`;
   - `copper_parts_batch` в `mechanical_workshop`.
3. Добавить добывающие рецепты или resource nodes для `clay`, `coal`, `iron_ore`, `copper`, `flax`, `herbs`, `mushrooms`, `seeds`.
4. Синхронизировать `shared/catalog/buildings.ts` с backend: либо временно скрыть здания без backend-типа, либо добавить серверные типы.
5. Добавить тест, который проверяет: каждый ресурс из цены здания есть в backend-каталоге, shared-каталоге и имеет production-output, field-output, forest-output, resource-node source или явно помечен как future. Стартовый инвентарь больше не должен считаться источником, кроме `coins: 50`.
