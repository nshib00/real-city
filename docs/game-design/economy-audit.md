# Аудит экономики Real City

Дата актуального среза: **3 ноября 2026 года**. Основа аудита — рабочий backend и каталог баланса v2; таблица ресурсов пересверена с runtime recipes, всеми 20 снимками уровней, полевым каталогом, стартовым инвентарём, loot и полной матрицей цен построек/апгрейдов. `data/balance/v2.json` совпадает с backend snapshot; то же подтверждено для `data/buildings/catalog-v2.json` и backend-каталога построек. В runtime v2 — **80 ресурсов, 72 типа построек, 37 recipe ID с 20 снимками уровня, 10 полевых типов**. Это аудит достижимости по коду и данным, а не подтверждение экономики на живом сервере: полный сценарий игрока с постоянной PostgreSQL-БД и балансными замерами не запускался.

## Итог

Экономические контракты уже существенно шире старого прототипа: **80 ресурсных ID, 72 типа построек, 37 производственных recipe ID с 20 снимками уровней каждый и 10 типов полевых культур**. Активно работают рубка леса, поля, рецепты промышленности, добыча с монстров и нефтяные вышки на нефтяных клетках. Старые тезисы о том, что весь ряд сырья/полей отсутствует, больше не верны.

При этом **прогрессия не замкнута**. В ценах есть ресурсы без повторяемого источника (`metal`, `gold_ingot`, `mechanism`, `reinforced_beams` и другие); часть поздних ресурсов существует только в редком loot/шансах. Железная руда настроена только как редкий выход шахты 10–12 уровней, однако уже апгрейд шахты до 3 уровня требует 46 `iron_ore`, а `iron_mine` не имеет активного добывающего рецепта. Отдельно сталь и железобетон замыкаются в цикл, а `dye_garden` требует собственные `dyes` при постройке. Seed-данные постоянного мира и полное прохождение экономики не подтверждены.

**Вывод:** проверка согласованности каталога не равна проверке проходимости. По пункту 21.15 остаётся незакрытым критерий «от первого поселения до поздней экономики без ресурсных тупиков».

## Источники и границы проверки

- Авторитетный runtime-каталог: `backend/internal/domain/catalog/balance.v2.json`, декодируемый в `backend/internal/domain/catalog/zz_runtime_balance.go`; типы ресурсов — `backend/internal/domain/economy/economy.go`.
- Цены и список зданий: `data/buildings/catalog-v2.json`, `backend/internal/domain/catalog/buildings.go`; shared-каталог сравнивается с серверным, но источником окончательного действия остаётся backend.
- Рецепты: `backend/internal/domain/catalog/economy.go`, runtime snapshot и `industry_specs_generated.go`. В snapshot — 37 recipe ID и 20 уровневых вариантов каждого. Для нефти есть отдельный runtime-генератор `OilExtractionRecipe`.
- Поля: `backend/internal/domain/economy/field.go`; применение/рост/сбор — `backend/internal/service/field.go`.
- Прямые источники: вырубка — `backend/internal/service/forest.go`; узлы — `backend/internal/service/resource.go` и адаптеры экономики; нефтяная добыча — `backend/internal/service/oil.go`; монстры и трофеи — `backend/internal/service/monster.go`.
- Список идей и ранее предлагаемые цепочки — `docs/game-design/resources-list.md`. Старые отметки «ресурс ещё не в каталоге» не считаются актуальными без сверки с runtime.

Реестры backend и UI совпадают по **80/80 resource ID**; `shared/catalog/buildings.ts` импортирует тот же `data/buildings/catalog-v2.json`, что используется при сверке каталога. При этом поле `source` в UI — только текстовая подсказка, не доказательство добываемости: сейчас оно ошибочно приписывает `metal`/`iron` литейной, `emerald_dust` огранке кристаллов и `super_mechanism` поздней мастерской. Для `metal`/`iron` активного источника нет; `emerald_dust` и `super_mechanism` существуют только в случайном луте стража руин и древнего колосса соответственно. UI-источник `fine_rope` в канатном дворе в целом верен, но не указывает, что это редкий выход с шансом 0,4–4% на цикл. Для `iron_ore` UI пишет «рудные жилы», тогда как фактический источник — низкошансовый выход поздней шахты.

Узлы `wood/stone/oil` из `backend/internal/adapter/memory/economy_repo.go` — локальная dev-фикстура. В production API при наличии БД создаётся PostgreSQL-репозиторий. В просмотренных миграциях найдено создание таблицы `resource_nodes`, но не найден универсальный seed сырьевых узлов. Oil well может создать/закрепить нефтяной узел на клетке при строительстве, но цена самой вышки включает `metal`, который сейчас не производится. Наличие методов claim/harvest/respawn само по себе не заселяет карту узлами.

## Цепочка получения каждого ресурса и применение в постройках

В колонке «Используется в постройках» `да` означает, что ID входит в стоимость/апгрейд, производственный рецепт или обслуживает действие постройки. Для системных величин и боеприпасов это отмечено отдельно. «Нет» означает, что в активной строительной матрице и рецептах текущего каталога потребителя не найдено. Редкий источник не считается гарантированной доступностью.

## Полнота использования и балансные выводы

### Недоступные или условно доступные цепочки

1. **Старт и сырьевые узлы.** Production-режим использует PostgreSQL-репозиторий; dev memory-узлы не переносятся в постоянный мир автоматически. Проверить seed и гарантировать новичку повторяемые wood/stone/прочие нужные источники до первой производственной постройки.
2. **Металл и нефть.** `oil_well` и `oil_refinery` содержат `metal` в цене, но recipe для metal отсутствует. Следовательно, нефть/fuel блокируются на шаге строительства даже при наличии нефтяных клеток. Уточнить, должен ли `metal` быть продуктом литейной, добываться из узлов или быть заменён на действующий ресурс.
3. **Руда и сталь.** `iron_ore` — редкая шахтная находка; затем `foundry` производит iron ingot, но `steelworks` требует reinforced concrete, а бетонная ветвь просит steel на выход reinforced concrete. Нужно разорвать зависимость стартовым рецептом стали, альтернативным источником/наградой или пересмотром цены одного из зданий.
4. **Поздняя механика.** `mechanism`, `gold_ingot`, `reinforced_beams`, `emerald_dust`, `aeolian_alloy` (и гарантируемость `tools`) стоят в действующих upgrade costs без текущего воспроизводимого источника. Каталог может валидировать ID, но не достижимость.
5. **Сверхредкие материалы.** Разовые монстры дают loot, но количество/шанс/доступный tier монстра не привязаны здесь к ожидаемой частоте. Для обязательных затрат нужен repeatable или гарантируемый путь; loot-only допускается только для необязательных улучшений с измеренной доступностью.
6. **Самозависимая краска.** Нужно убрать `dyes` из первого уровня `dye_garden` либо предоставить отдельный источник до него. Без этого ветка не запускается штатно.

### Неиспользуемые или слабо связанные ресурсы

Кандидаты на включение в следующий sink либо явное исключение из активной экономики: `sugar_cane`, `crystal_fruit`, `paints`, `super-windleaf`, `amber_essence`, `kaolin`, `stone_heart`, `fine_rope`, `oleoresin`. Перед балансировкой перепроверь всю build-cost матрицу и поля всех уровней: возможны отдельные поздние применения; даже если ресурс встречается в одной цене, это не гарантирует жизнеспособную производственную ветку.

### Качество баланса, которое пока нельзя подтвердить

- Значения output/duration/workers в каталогах есть, но нет единого расчёта себестоимости, чистого output за час и числа циклов до типового апгрейда для всех 37 производств и 10 полей.
- Не проверена достаточность населения после одновременного запуска производства, поля, стройки и ремонта; FieldService резервирует население на стадии, но интегральный лимит зависит от жилья/состояния поселения.
- Не рассчитана стоимость потерь при разрушении/восстановлении построек и возобновляемость дефицитных входов.
- Coin production присутствует в полях, песчаном карьере, лесорубке и rope yard; сумма coin sinks и storage capacity не сведена к производству на типовом игровом профиле.
- Шансы редких выходов присутствуют в уровнях, но без симуляции на типичном темпе нельзя утверждать, что обязательные редкости достижимы вовремя.

## Минимальный следующий пакет работ

Не начинать сразу с десятков новых заводов. Минимальный пакет для снятия наиболее опасных блокировок:

1. **Постоянная тестовая карта:** добавить/проверить seed базовых повторяемых сырьевых источников и стартового пути в PostgreSQL; исключить ложное использование memory fixtures.
2. **Минимальная стальная петля:** определить один малый источник `metal`/`steel` до `steelworks` либо изменить стоимость/рецепты так, чтобы `steel` и `reinforced_concrete` перестали требовать друг друга до своего производства.
3. **Удалить circular unlock:** убрать `dyes` из первого уровня `dye_garden` (или добавить источник до постройки); подключить регулярный `fiber` source для `weaving_yard` либо изменить recipe.
4. **Таблица обязательных затрат:** автоматически пройти все 72 здания и уровни, сопоставить каждый ID стоимости с repeatable source и отметить RNG-only/нет источника; временно исключить из доступного unlock только те поздние затраты, для которых ещё нет цепочки.
5. **Один сквозной сценарий:** чистый игрок → получение базовых ресурсов → постройка/апгрейд seed/flax/ресурсного здания → craft → первый steel/concrete unlock → повтор после потери здания; ни один шаг не должен требовать внешнего grant.

Пакет считается завершённым, когда эти шаги проходят на изолированной PostgreSQL-БД без ручного редактирования инвентаря, все ресурсы стоимости имеют подтверждённую цепочку, а оставшиеся необязательные редкости явно помечены как опциональные. После этого расширять производственные роли для `sugar_cane`, `crystal_fruit`, `paints`, `amber_essence`, `fine_rope` и проектных ресурсов.
