# Аудит начисления опыта за действия с постройками

> Исторический снимок до внедрения общего каталога XP. Пробелы строительства, апгрейда, сбора и PvP-уничтожения ниже устранены последующей реализацией. Действующие значения и правила: [спецификация XP](../buildings/experience.md), таблицы в спеках построек и `backend/internal/domain/catalog/building_xp.json`. Отдельные отсутствующие механики (например, рецепты шахты и канатного двора) этим не добавлялись.

Дата: 30 октября 2026 года. Проверено текущее рабочее дерево проекта, включая незакоммиченные изменения. Это анализ реализации; игровая логика в рамках аудита не изменялась.

## Итог

Проверены **72 типа обычных построек и 12 типов мировых руин**. У всех 84 типа есть хотя бы один пробел: **за уничтожение чужой постройки XP сейчас не начисляется**.

- У **51 из 73** обычных типов полностью отсутствуют записи наград за строительство, работу и уничтожение.
- У **22 типов** записи есть: пять в основном XP-каталоге и ещё 17 в сгенерированном промышленном каталоге. Наличие чисел само по себе не означает наличие обработчика награды.
- У стекольной мастерской таблица XP заканчивается уровнем 9, а каталог построек содержит уровни 1–12: уровни 10–12 возвращают нулевую награду.
- У **18 типов** реализованы сбор урожая или завершение производства, но награда за них равна нулю. Ещё у стекольной мастерской есть указанный пробел уровней 10–12.
- У шахты и канатного двора значения `Work` есть, но соответствующих производственных рецептов в действующем каталоге нет: сейчас их нельзя считать работающей наградой за производство.
- У всех **12 руин** отсутствует XP за завершение восстановления и уничтожение.
- Ремонт, добровольный снос, перенос, отмены, промежуточные стадии выращивания и обслуживание защиты также не начисляют XP. Для таких действий перед реализацией нужно явно определить политику награды, включая допустимый ноль.

## Что именно проверялось

Источники истины для состава и уровней: [buildings.v2.json](../../backend/internal/domain/catalog/buildings.v2.json), [balance_data.go](../../backend/internal/domain/catalog/balance_data.go), [balance.v2.json](../../backend/internal/domain/catalog/balance.v2.json), [zz_runtime_balance.go](../../backend/internal/domain/catalog/zz_runtime_balance.go). Включены все типы каталога, в том числе доступные только через улучшение и типы без реализованной основной работы.

Таблицы XP: [experience.go](../../backend/internal/domain/catalog/experience.go) и [industry_specs_generated.go](../../backend/internal/domain/catalog/industry_specs_generated.go). Поиск всех записей `buildingXP`, вызовов `ExperienceForBuilding` и `Award` выполнен по серверному коду. За пределами таблицы или диапазона уровня `ExperienceForBuilding` возвращает нули; `ExperienceService.Award` молча пропускает `amount <= 0`.

Сервисы XP подключены в API и worker. Ни отсутствие уведомления на клиенте, ни значение поля `Destruction` не использовались как доказательство фактического начисления.

Аудит статический: сервер и база не запускались. Указанный статус описывает наличие серверной ветки начисления и данных награды, а не проверку всех аварийных сценариев её доставки.

### Пробелы в награде за работу

Нулевая награда при реализованном действии:

- Сбор урожая: грядка ветролиста, травяная грядка, грибница, тростниковая грядка, красильный сад, масличное поле, сахарная грядка, кристальная оранжерея.
- Сбор продукции / завершение производственного задания: мастерская, кузница, лесопильный двор, песчаный карьер, глиняный карьер, нефтяная вышка, камнедробилка, химическая мастерская, осадный двор, резонансная лаборатория.
- Частичное покрытие: стекольная мастерская, уровни 10–12.

Для шахты и канатного двора нужно отдельно восстановить/добавить производственную механику либо явно зафиксировать её отсутствие. Нельзя устранить этот пробел одним добавлением чисел XP. Другие промышленные типы с «—» тоже не имеют рецептов в действующем каталоге; название или категория постройки не доказывают наличие производства.

## Покрытие действий и причины пробелов

| Действие | Текущее поведение | Область доработки |
| --- | --- | --- |
| Завершение строительства | Общий вызов `awardCompletionXP` есть; мгновенное строительство тоже его вызывает | Добавить данные для 51 обычного типа и 12 руин |
| Завершение улучшения, включая смену типа | Использует тот же `Completion` итогового типа/уровня | Покрыть недостающие типы и уровни; проверить переходы жилья и дорог |
| Ускоренное завершение | Вызывает `awardCompletionXP`; отдельной награды за оплату ускорения нет | То же покрытие, без двойной награды |
| Сбор обычного урожая | `HarvestField` начисляет `Work` | Покрыть восемь перечисленных полей |
| Сбор суперурожая | Начисляет `Work × 3`; при нулевом `Work` результат тоже нулевой | Покрыть те же поля; проверить множитель |
| Запуск/переход стадии выращивания | `AdvanceField` не начисляет XP | Определить, нужен ли отдельный XP или только за урожай |
| Сбор продукции | `ProductionService.CompleteAt` начисляет `Work` один раз на задание | Покрыть десять типов и верхние уровни стекольной мастерской |
| Готовность производства по таймеру | `ReadyAt` переводит задание в ready; XP начисляется при сборе, а не при готовности | Сохранить одно выбранное событие награды |
| Захват нефтяного узла при строительстве вышки | `ClaimOilWell` не вызывает общий `ResourceService.Claim` и не даёт его 5 XP | Явно решить, нужна ли отдельная награда сверх строительства |
| Восстановление/освоение руин | Общий путь завершения есть, данных XP нет | Все 12 типов |
| Урон чужой постройке оружием | `CombatService.damageBuilding` не вызывает XP | Определить политику за урон; исключить повторное получение за один результат |
| Уничтожение чужой постройки оружием | Смена состояния на ruined/удаление не сопровождается XP | Все 84 типа, когда цель допустима по правилам PvP |
| Уничтожение чужой постройки созданным игроком монстром | `MonsterAI` применяет урон, но не награждает `CreatorID` за уничтожение | Все допустимые цели; определить получателя и ключ события |
| Гибель постройки от дикого монстра | Нет XP игроку за потерю | Не назначать получателя автоматически; это отдельное дизайнерское решение |
| Успешный ремонт | `CompleteRepairs` восстанавливает HP без XP | Все допустимые уцелевшие постройки, включая восстановленные руины |
| Добровольный снос/продажа своей постройки | `Demolish` возвращает ресурсы/население, но не XP; чужую снести этим методом нельзя | Явно определить награду или обоснованный ноль |
| Перенос/поворот | `Relocate` не начисляет XP | Определить нулевую политику для повторяемой операции |
| Отмена строительства/производства | XP нет | Зафиксировать ноль либо правило; не награждать незавершённый результат |
| Перезарядка ловушки, включение/выключение орудия | XP нет | Явно определить политику обслуживания |

Ключевые обработчики: [building.go](../../backend/internal/service/building.go), [field.go](../../backend/internal/service/field.go), [production.go](../../backend/internal/service/production.go), [pvp.go](../../backend/internal/service/pvp.go), [monster_ai.go](../../backend/internal/worker/simulation/monster_ai.go), [repair.go](../../backend/internal/service/repair.go), [oil.go](../../backend/internal/service/oil.go).

### Уничтожение: данные есть, исполнения нет

Поле `BuildingXP.Destruction` заполнено для тех же 22 типов, но **не используется для начисления** ни при прямой атаке оружием, ни при атаке созданного монстра. Простое дополнение XP-таблицы не исправит уничтожение: нужен вызов награды при подтверждённом переходе живой чужой постройки в разрушенное состояние.

`BuildingService.Demolish` требует владельца и не является способом сноса чужой постройки. Награда за PvP должна находиться в боевой логике. Для руин и нефтяных вышек нужно учитывать удаление объекта после разрушения и не терять сведения о типе, уровне и владельце.

### Защита: часть XP уже работает

У пушки (`defense_cannon`), болтомёта (`defense_bolt_thrower`) и грозовой катушки (`defense_storm_coil`) убийство дикого монстра начисляет владельцу `max(1, MaxHealth / 10)` XP через [cannon.go](../../backend/internal/service/cannon.go). Для кольев (`defense_stakes`) и смоляной западни (`defense_resin_snare`) аналогичная награда есть в `MonsterAI`.

Награда привязана к убийству монстра, не к каждому выстрелу/срабатыванию и не к `BuildingXP.Work`. Убийство созданного игроком монстра в этих ветках исключено из награды. Следовательно, эти пять типов нельзя называть полностью лишёнными XP за работу, хотя за их строительство и улучшение XP нет.

Для мастерской автоматонов и вольера союзников наличие каталожных характеристик базы не подтверждает работающую ветку XP: отдельной награды за их действия в проверенных вызовах `Award` нет.

### Что не следует смешивать с наградами построек

[ResourceService](../../backend/internal/service/resource.go) начисляет 5 XP за первое присвоение ресурсного узла и 1 XP за сбор. Это самостоятельные узлы мира; данные награды не доказывают покрытие шахты, карьеров или вышки. Рубка леса и убийства монстров также имеют собственные награды.

Рынок работает через операции торговли, а не производственный рецепт; отдельной награды XP за торговые операции не найдено. Склады и жильё обеспечивают вместимость/население; отдельного действия сбора продукции в проверенной производственной механике у них нет. Нельзя автоматически считать каждое изменение инвентаря событием XP постройки.

## План последующей реализации

1. Утвердить перечень награждаемых результатов: строительство, завершённый апгрейд, урожай, сбор продукции, восстановление руин, ремонт, уничтожение чужой постройки. Для обслуживания, отмен, переноса, добровольного сноса, торговли и урона без уничтожения явно записать положительную награду либо нулевую политику с причиной.
2. Дополнить каталог XP для 51 типа и 12 руин; расширить стекольную мастерскую до уровня 12. Согласовать величины с существующим балансом, не подставлять произвольную одинаковую награду всем.
3. Подключить `Destruction` к прямым и отложенным атакам оружием и уничтожению созданными монстрами. Получатель — действующий атакующий/создатель, а не владелец жертвы; запретить награду за свои здания и повторное разрушение.
4. Добавить отдельное правило ремонта, если он награждается. Строительная награда и награда ремонта должны иметь разные ключи событий.
5. Для шахты, канатного двора и прочих типов без основной механики сначала определить саму механику; не отмечать XP реализованным по одному наличию чисел.
6. Сохранять результат действия и награду в одной транзакции либо обеспечивать надёжное повторное начисление. Текущие обработчики местами сохраняют состояние до вызова XP, поэтому сбой начисления после сохранения требует отдельной проверки.
7. Покрыть каталог и обработчики тестами, затем обновить этот аудит по фактическому результату.

## Требование для каждой новой постройки

При добавлении типа обязательно задавать **политику XP для всех его действий и достижимых уровней**. Положительная награда должна сопровождаться серверным вызовом начисления; осознанный ноль — явным правилом с причиной. Отсутствие записи не должно молча означать ноль.

Это требование зафиксировано здесь для следующего этапа; автоматическая проверка полноты пока не реализована.

Рекомендуемые обязательные проверки:

- Полный обход `AllBuildings()` и `RuinSpecs`, всех уровней, переходов между типами, полевых культур и производственных рецептов. Новый тип без политики должен ломать тест.
- Завершение обычного, мгновенного, ускоренного строительства и апгрейда; отдельные проверки переходов между типами.
- Обычный и суперурожай, сбор каждой группы продукции, верхние уровни стекольной мастерской.
- Прямая и отложенная атаки, последний удар созданного монстра, руина/вышка с удалением объекта, конкурентный последний удар. Награда ровно один раз.
- Ремонт: успешное завершение, отмена из-за смены состояния/владельца/уровня, повторная обработка.
- Повтор запроса/доставка события, перезапуск worker и ошибка сохранения XP: нет удвоения и потери награды.
- Явные нулевые политики: собственное здание, уже разрушенная цель, отмена, перенос и прочие согласованные исключения.

Текущие [experience_test.go](../../backend/internal/service/experience_test.go) проверяют отдельные примеры строительства, урожая, производства и идемпотентности; [industry_specs_test.go](../../backend/internal/domain/catalog/industry_specs_test.go) проверяет промышленную группу. Полного требования покрытия всех типов и действий сейчас нет. В тесте примеров XP даже зафиксирован нулевой результат для землянки: при внедрении общего покрытия его потребуется пересмотреть.
