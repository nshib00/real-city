# Профиль игрока и система уровней

## Цель

Профиль игрока должен быть не только карточкой с ником, но и кратким срезом его положения в общем мире: где находится его город, чем он силен, насколько активен, кому принадлежит, насколько опасен для соседей и какие у него достижения.

Система уровней должна давать долгосрочную цель без превращения игры в вертикальную гонку силы. Уровень показывает опыт игрока и постепенно открывает удобство, престижные элементы и расширение стратегических возможностей, но не должен сам по себе делать низкоуровневого игрока беспомощным.

## Состав профиля

### Основная идентичность

- `playerId` - внутренний неизменяемый идентификатор.
- `displayName` - публичное имя игрока.
- `avatarId` - выбранный портрет или герб.
- `bannerId` - фон карточки профиля.
- `level` - текущий уровень.
- `xp` - общий накопленный опыт.
- `title` - выбранный титул, если открыт.
- `createdAt` - дата создания аккаунта.
- `lastSeenAt` - последняя активность, округленная для публичного отображения.

Публичная карточка должна показывать имя, аватар, уровень, титул, группу, главную территорию и несколько важных показателей. Технические данные, точные склады, внутренние cooldown'ы и приватные координаты не должны раскрываться через публичный профиль.

### Карта и владение

- `homeCenterId` - главное здание или центр города игрока.
- `homeChunk` - примерная область главного поселения.
- `territoryScore` - оценка контролируемой территории.
- `protectedObjectsCount` - количество защищенных объектов.
- `vulnerableObjectsCount` - количество уязвимых объектов.
- `frontierDistance` - насколько далеко игрок расширился от основного центра.

Эти поля нужны, чтобы профиль был связан с главной идеей игры: игрок живет на общей карте, а не в изолированном меню.

### Экономика

- `economyScore` - агрегированная экономическая оценка.
- `productionScore` - сила производства по всем активным зданиям.
- `storageScore` - емкость складов и устойчивость к потерям.
- `tradeScore` - участие в рынке и обменах.
- `resourceClaims` - количество удерживаемых ресурсных узлов.

В публичном профиле лучше показывать ранги или категории, а не точные запасы. Точные ресурсы должны оставаться приватными, иначе профиль станет инструментом для выбора легких жертв.

### Оборона и риск

- `defenseScore` - суммарная оценка обороны.
- `attackScore` - опыт атак, атак и боевых действий.
- `monsterThreatHandled` - сколько угроз PvE было отбито.
- `recentDamageTaken` - недавний ущерб, отображаемый как состояние: спокойно, тревожно, под давлением.
- `protectionStatus` - активная защита новичка, перемирие, обычный режим или спорная зона.

Важно разделять боевой престиж и защитную силу. Игрок может быть сильным строителем, торговцем или защитником, а не только рейдером.

### Социальная часть

- `groupId` - гильдия, союз или группа игрока.
- `groupRole` - роль внутри группы.
- `reputation` - репутация за честную торговлю, помощь и договоры.
- `diplomacyTags` - публичные метки: торговец, защитник, исследователь, налетчик, строитель.
- `mutedUntil` / `chatRestrictions` - служебные ограничения, не обязаны быть публичными.

Группы и репутация должны помогать формировать политику карты: кому доверять, с кем торговать, кого приглашать в оборону, кого опасаться.

### Достижения и история

- `badges` - открытые значки.
- `featuredBadges` - 3-5 значков, закрепленных игроком в профиле.
- `milestones` - важные события: основание города, первое удержание ресурса, первая успешная оборона.
- `seasonStats` - сезонная статистика, если появятся сезоны.
- `lifetimeStats` - общая статистика за все время.

История должна подчеркивать участие игрока в живом мире: строительство, споры за ресурсы, оборона, торговля, PvE-угрозы.

## Публичные и приватные данные

Публично можно показывать:

- имя, аватар, уровень, титул;
- группу и роль;
- примерную область города;
- выбранные значки;
- агрегированные оценки экономики, обороны, торговли и атак;
- общие достижения;
- статус активности в грубой форме.

Приватными должны оставаться:

- точные ресурсы на складах;
- точные координаты уязвимых запасов и построек, если игрок их не видит на карте сам;
- активные боевые таймеры, невидимые через карту;
- внутренние антифрод-метрики;
- персональные настройки аккаунта;
- технические идентификаторы сессионного уровня.

## Очки опыта

Опыт начисляется за действия, которые создают полезную активность на общей карте:

| Источник опыта | Принцип начисления |
| --- | --- |
| Строительство | За завершение здания, с учетом стоимости и времени строительства. |
| Улучшения | За апгрейды, которые меняют стратегическую ценность объекта. |
| Ресурсные узлы | За первое захватывание, удержание и успешную доставку ресурсов. |
| Логистика | За создание дорог, связей и маршрутов между важными объектами. |
| Оборона | За отражение атак и защиту атакуемых объектов. |
| PvE | За уничтожение или оттеснение монстров, угрожающих поселению. |
| Торговля | За завершенные сделки с другими игроками. |
| Групповая игра | За вклад в общие цели группы без бесконечного фарма. |
| Исследование | За открытие новых областей, руин, залежей и опасных зон. |

Опыт не должен бесконечно фармиться одним безопасным действием. Для повторяемых источников нужны дневные или недельные soft caps, убывающая отдача и проверки на злоупотребления.

### Рекомендуемые ограничения

- Не давать опыт за отмененное строительство.
- Не давать полный опыт за разрушение своих зданий и повторную постройку.
- Сильно снижать опыт за действия между связанными аккаунтами или подозрительно повторяемыми целями.
- Начислять основной опыт после завершения серверного действия, а не после клиентского клика.
- Хранить события опыта на сервере как auditable log: кто, за что, сколько, когда, по какому правилу.

### Подключенные начисления

- Каждая успешная фаза рубки леса дает `1 XP`; полная рубка клетки с плотностью `3` дает `3 XP`.
- Завершение строительства/апгрейда, сбор урожая и сбор продукции дают XP **только** для типов и уровней, где в спецификации постройки указано численное значение. Сейчас это Сад семян, Льняное поле, Стекольная мастерская, Шахта и Канатный двор. Значения хранятся в серверном каталоге без расчетных замен для остальных построек.
- Для редкого урожая Сада семян и Льняного поля используется указанный в спеках множитель `3` к обычному XP за сбор. Отдельное начисление за каждую промежуточную фазу роста не включено: в спеках указан XP за сбор, но не за фазы.
- Убийство монстра игроком дает `max(1, max_health / 10) XP` по типу монстра. За удар без убийства XP нет.
- Первый захват ресурсного узла дает `5 XP`, успешный сбор из него — `1 XP`. Повторное нажатие «захватить» не дает новый XP.
- Начисление хранится в `player_xp_events` с уникальным ключом игрового события. Повторная обработка того же события не увеличивает XP второй раз.
- Самостоятельный снос постройки не считается уничтожением в бою и XP не дает. XP за уничтожение чужой постройки будет начисляться только после появления валидного серверного боевого действия; сейчас такого действия нет.

## Уровни

Уровней ограниченное количество: каждый должен ощущаться как заметный этап развития. Порог следующего уровня растет значительно быстрее предыдущего, поэтому ранние уровни объясняют игру, а поздние становятся долгосрочным престижем. Разрыв между уровнями увеличивается по экспоненциальной логике: каждый следующий этап требует существенно больше опыта, чем предыдущий.

| Уровень | Название | Общий опыт | Опыт от прошлого уровня | Иконка | Смысл этапа |
| --- | --- | ---: | ---: | --- | --- |
| 1 | уровень 1 | 0 | 0 | `Tent` | Игрок появляется на карте, ставит первый центр и изучает базовые действия. |
| 2 | уровень 2 | 200 | 200 | `MapPinned` | Игрок начинает осознанно выбирать территорию, видеть границы и ресурсные точки. |
| 3 | уровень 3 | 700 | 500 | `Hammer` | Поселение получает первые производственные связи и базовые улучшения. |
| 4 | уровень 4 | 1 900 | 1 200 | `Shield` | Игрок сталкивается с обороной, монстрами и риском расширения. |
| 5 | уровень 5 | 4 700 | 2 800 | `Route` | Главной темой становятся дороги, склады и удержание ближайших ресурсных узлов. |
| 6 | уровень 6 | 11 200 | 6 500 | `Warehouse` | Игрок закрепляет устойчивую экономику и учится переживать потери. |
| 7 | уровень 7 | 26 200 | 15 000 | `LandPlot` | Игрок управляет несколькими зонами влияния и спорными границами. |
| 8 | уровень 8 | 61 200 | 35 000 | `Handshake` | Игрок становится заметным участником торговли, договоров и локальных конфликтов. |
| 9 | уровень 9 | 141 200 | 80 000 | `TowerControl` | Игрок удерживает удаленные объекты и строит более сложную оборонную сеть. |
| 10 | уровень 10 | 321 200 | 180 000 | `Castle` | Поселение превращается в крупный центр силы на карте. |
| 11 | уровень 11 | 721 200 | 400 000 | `Network` | Игрок влияет на несколько соседних районов через логистику, рынок и союзников. |
| 12 | уровень 12 | 1 621 200 | 900 000 | `Gem` | Прогресс становится долгосрочным престижем и требует стабильной активности. |
| 13 | уровень 13 | 3 621 200 | 2 000 000 | `Landmark` | Игрок закрепляет заметное историческое присутствие в мире. |
| 14 | уровень 14 | 8 121 200 | 4 500 000 | `Crown` | Игрок входит в число ключевых сил региона. |
| 15 | уровень 15 | 18 121 200 | 10 000 000 | `Trophy` | Максимальный престижный уровень для игроков, влияющих на большой участок мира. |

Иконки указаны как названия из библиотеки `lucide-react`, потому что она уже подходит для интерфейсных пиктограмм. Для финального арт-пайплайна каждую иконку можно заменить на изометрический медальон в том же смысловом образе.

## Открытия по уровням

Уровень не должен давать прямой множитель урона или производства. Лучше открывать ширину выбора, социальный статус и удобство управления.

| Уровень | Открытия |
| --- | --- |
| 1 | Базовое строительство, стартовый центр, 1 активная область поселения, базовый чат. |
| 2 | Отображение границ влияния, простые дороги, закрепление 1 значка в профиле. |
| 3 | Улучшения базовых зданий, расширенный инспектор производства, 2 закрепленных значка. |
| 4 | Базовые стены и башни, журнал угроз, публичный оборонный статус. |
| 5 | Торговые маршруты, рынок, расширенные складские уведомления, титул профиля. |
| 6 | Дополнительные складские правила, настройки уведомлений о потерях, 3 закрепленных значка. |
| 7 | Дополнительная область влияния, правила приоритета логистики, профильные метки специализации. |
| 8 | Расширенные роли в группе, вклад в групповые цели, дипломатические метки. |
| 9 | Улучшенные фильтры журнала событий, расширенный обзор угроз, профильный статус специализации. |
| 10 | Престижная рамка профиля, расширенная история достижений, лидерские доски по направлениям. |
| 11 | Расширенная статистика влияния на карту, дополнительные групповые метрики вклада. |
| 12 | Престижный медальон профиля, сезонные витрины достижений, расширенный архив событий. |
| 13 | Расширенные косметические варианты профиля и карты без прямого усиления силы. |
| 14 | Высокий престиж в публичных рейтингах и дополнительные слоты для избранных достижений. |
| 15 | Максимальная престижная рамка, постоянная отметка максимального уровня, постмаксимальный счет опыта. |

Если какое-то открытие критично для базового PvP или защиты, его нельзя держать слишком поздно. Поздние уровни должны усиливать глубину и престиж, а не закрывать обязательные инструменты выживания.

## Расчет прогресса

Для отображения прогресса нужны два значения:

- общий опыт игрока;
- прогресс внутри текущего уровня.

Пример:

```ts
type PlayerLevelProgress = {
  level: number
  title: string
  icon: string
  totalXp: number
  currentLevelXp: number
  nextLevelXp: number | null
  progressToNextLevel: number
}
```

Для 15 уровня `nextLevelXp` равен `null`, а прогресс можно показывать как престижный счет после максимального уровня. Это позволяет продолжать получать опыт без добавления бесконечной лестницы уровней.

## Роли профиля в интерфейсе

### Свой профиль

Показывает:

- текущий уровень и прогресс до следующего;
- открытые возможности;
- закрепленные значки;
- экономику, оборону, торговлю и атаки;
- недавние события;
- подсказку, какие действия быстрее всего приблизят следующий уровень.

### Чужой профиль

Показывает:

- имя, аватар, уровень и титул;
- группу;
- примерную зону главного поселения;
- публичные специализации;
- выбранные достижения;
- агрегированную силу без раскрытия точных ресурсов.

### Профиль группы

Не заменяет профиль игрока, но должен использовать похожую структуру:

- название;
- герб;
- участники;
- роли;
- общая территория;
- групповые достижения;
- дипломатический статус;
- вклад участников.

## Баланс и защита новичков

Чтобы уровни не ломали общую карту:

- PvP-цели должны оцениваться не только по уровню, но и по расстоянию, защите, стоимости цели и текущему статусу игрока.
- Новичок не должен становиться выгодной целью только из-за слабого уровня.
- Опыт за атаки должен зависеть от реального риска и ценности цели, а не от количества атак.
- Защита новичка должна сниматься постепенно: сначала игрок учится строить и обороняться, затем выходит в обычный режим карты.
- Игрок высокого уровня не должен получать значимый опыт за давление на заведомо слабые цели.

## Минимальная модель для MVP

Для первой реализации достаточно следующих полей:

```ts
type PlayerProfile = {
  id: string
  displayName: string
  avatarId: string
  level: number
  xp: number
  title: string | null
  groupId: string | null
  homeCenterId: string | null
  territoryScore: number
  economyScore: number
  defenseScore: number
  attackScore: number
  tradeScore: number
  badges: string[]
  featuredBadges: string[]
  createdAt: string
  lastSeenAt: string
}
```

Позже модель можно расширить приватными статистиками, сезонными данными, журналом начисления опыта и настройками публичности.

## Критерии готовности системы

- Профиль объясняет положение игрока на общей карте.
- Уровень и опыт рассчитываются сервером.
- Все начисления опыта проходят через журнал событий.
- Публичный профиль не раскрывает точные ресурсы и скрытую уязвимость игрока.
- У каждого уровня есть название, иконка, порог опыта и понятный смысл.
- Поздние уровни требуют значительно больше опыта, чем ранние.
- Открытия по уровням не создают непреодолимое преимущество над новичками.
