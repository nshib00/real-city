# План моделей грядки ветролиста для уровней 4-11

## Общие правила

- Все уровни используют единую плоскую клетку земли из `frontend/public/assets/terrain/tiles/grass.png`.
- Runtime PNG: `512x384`, anchor `[256, 292]`, видимая ширина клетки около `278 px`, как у ратуш и землянок.
- Основание `construction` и `damaged` копирует ground из `active` того же уровня без перекраски, сдвига и изменения высоты.
- Все столбы, рейки, бревна, камни, мешки, веревочные стойки и обломки должны нижней гранью стоять на земле, грядке, цоколе или другой видимой опоре.
- Бортики, стены и рамы должны соединяться без пустых зазоров между столбами и горизонтальными элементами.
- Каждый новый материальный ресурс из стоимости уровня должен быть заметен в самой модели, а не только лежать рядом как запас.
- Прогресс уровней должен читаться в масштабе карты: выше качество рамы, больше устойчивых материалов, плотнее система поддержки листьев, но грядка остается низким полевым объектом и не превращается в теплицу.
- Супер-ветролист должен расти по заметной шкале: `super_stage01` - маленько-средний мутировавший побег уже выше обычной первой стадии, `super_stage02` заметно крупнее, `super_stage03-super_stage05` последовательно расширяют листья и высоту, `super_stage06` - гигантский полностью зрелый листовой куст. По сравнению с прежними ранними вариантами поздние супер-стадии нужно делать примерно в `1,5-2` раза крупнее и поддерживать их стойками/веревками, если листья начинают нависать над рамой.
- При генерации через Windows Blender из WSL использовать UNC-путь к проекту, например `\\wsl.localhost\Debian\home\nshib\projects\real-city`, потому что путь `/home/nshib/projects/real-city` внутри Windows Blender не виден. Это касается не только записи PNG/GLB, но и проверок существования файлов: `terrain/grass.png` нужно проверять и загружать через UNC, иначе Blender может сгенерировать модель без реальной terrain-текстуры.
- Для runtime PNG в текущей связке Windows Blender + MCP надежный путь такой: создавать изолированную сцену на один ассет, ставить эталонную ортографическую камеру и писать PNG через `bpy.ops.render.opengl(write_still=True, view_context=False)`. Общая сцена со множеством коллекций и обычный `bpy.ops.render.render(write_still=True)` в этой среде могут давать полностью прозрачные PNG (`alpha 0`) даже при видимых объектах.

## Уровень 4

Стоимость: `coins 31000`, `flax 20`, `windleaf 3`, `planks 13`.

Модель:

- Аккуратная дощатая рама выше уровня 3, но все еще низкая.
- Часть боков заменена плетением из льна и тонких планок.
- На переднем углу маленький знак ветролиста или подвеска с листом.
- Крупнее обычные листья на стадии 4, но без редкого свечения.

Ресурсные признаки:

| Ресурс | Видимая деталь |
| --- | --- |
| `flax` | плетеные боковые вставки и светлые подвязки |
| `windleaf` | связки сушеных листьев на табличке/углах |
| `planks` | ровная дощатая рама и верхние планки |

## Уровень 5

Стоимость: `coins 92400`, `windleaf 7`, `planks 34`, `rope 5`.

Модель:

- Появляется веревочная сетка над грядкой для поддержки листьев.
- Углы усилены более толстыми стойками.
- Дощатая рама плотнее и чище, с видимыми поперечинами.
- На готовой стадии листья привязаны к сетке и занимают больше площади.

Ресурсные признаки:

| Ресурс | Видимая деталь |
| --- | --- |
| `windleaf` | больше живых и сушеных листьев по краям |
| `planks` | массивная устойчивая рама |
| `rope` | натянутая сетка и угловые узлы |

## Уровень 6

Стоимость: `coins 143200`, `planks 67`, `stone 19`, `rope 14`, `windleaf 9`.

Модель:

- Камни появляются как низкие угловые опоры и небольшие боковые подпятники.
- Веревочная сетка становится плотнее и выше.
- Рама выглядит тяжелее: толстые доски, надежные стыки, меньше временности.
- Земля внутри грядки более организована: ровные ряды, подпорки под листья.

Ресурсные признаки:

| Ресурс | Видимая деталь |
| --- | --- |
| `planks` | толстая деревянная рама |
| `stone` | каменные угловые опоры |
| `rope` | плотная поддерживающая сетка |
| `windleaf` | развитые листья и подвязанные побеги |

## Уровень 7

Стоимость: `coins 230500`, `planks 130`, `stone 40`, `rope 26`, `fabric 15`.

Модель:

- Добавлены защитные тканевые ленты по ветру и маленькие флажки.
- Камни образуют не только углы, но и короткие боковые вставки.
- Веревки идут в два уровня: нижний удерживает раму, верхний поддерживает листья.
- Силуэт остается низким, но становится более ремесленным и ухоженным.

Ресурсные признаки:

| Ресурс | Видимая деталь |
| --- | --- |
| `planks` | частые деревянные планки и поперечины |
| `stone` | боковые каменные вставки |
| `rope` | двухуровневые натяжения |
| `fabric` | тканевые ленты и флажки |

## Уровень 8

Стоимость: `coins 361000`, `premium_planks 1`, `stone_block 18`, `rope 49`, `fabric 32`.

Модель:

- Низкий цоколь из каменных блоков заменяет рыхлые камни.
- Одна светлая premium-доска выделяется как центральная верхняя планка.
- Ткань становится аккуратной защитной обвязкой, без превращения в навес.
- Веревки формируют ровную сетку для крупных листьев.

Ресурсные признаки:

| Ресурс | Видимая деталь |
| --- | --- |
| `premium_planks` | одна светлая гладкая планка-акцент |
| `stone_block` | низкий блочный цоколь |
| `rope` | регулярная сетка |
| `fabric` | аккуратные защитные ленты |

## Уровень 9

Стоимость: `coins 565000`, `premium_planks 2`, `stone_block 30`, `fabric 57`, `iron_ingot 2`.

Модель:

- Цоколь становится выше и ровнее, с отдельными читаемыми блоками.
- Две premium-доски видны на переднем и заднем крае.
- Появляются темные металлические фиксаторы на углах и стыках.
- Тканевые элементы плотнее, но не закрывают урожай сверху.

Ресурсные признаки:

| Ресурс | Видимая деталь |
| --- | --- |
| `premium_planks` | две светлые планки |
| `stone_block` | более высокий блочный цоколь |
| `fabric` | плотные боковые ленты |
| `iron_ingot` | темные крепежи и скобы |

## Уровень 10

Стоимость: `coins 817400`, `premium_planks 4`, `stone_block 61`, `iron_ingot 5`.

Модель:

- Почти элитная грядка: ровный каменный контур, чистые стыки, минимум временных деталей.
- Четыре premium-доски формируют светлую верхнюю рамку по сторонам.
- Металлические стяжки читаются на углах, боках и поперечинах.
- Листья крупные, хорошо поддержанные, без хаотичного роста за пределы клетки.

Ресурсные признаки:

| Ресурс | Видимая деталь |
| --- | --- |
| `premium_planks` | светлая верхняя рама из четырех планок |
| `stone_block` | полный каменный контур |
| `iron_ingot` | стяжки, скобы и угловые пластины |

## Уровень 11

Стоимость: `coins 1185000`, `premium_planks 7`, `iron_ingot 9`, `gold_ingot 2`, `emerald_dust 1`.

Модель:

- Престижная каменно-деревянная рама без роста высоты здания.
- Premium-доски образуют гладкий дорогой верхний периметр и две поперечины.
- Железные крепления становятся регулярной системой стяжек.
- Два золотистых фиксатора размещены на передних углах или центральных замках.
- Изумрудная пыль показана мягким зеленым акцентом на жилках готовых листьев и маленькой полосой в раме, без яркого магического взрыва.

Ресурсные признаки:

| Ресурс | Видимая деталь |
| --- | --- |
| `premium_planks` | дорогой верхний периметр и поперечины |
| `iron_ingot` | регулярные темные стяжки |
| `gold_ingot` | два золотистых фиксатора |
| `emerald_dust` | мягкий зеленый блеск жилок и вставки в раме |

## Состояния

Для каждого уровня 4-11 нужны:

| Состояние | Требование |
| --- | --- |
| `stage01-stage04` | рост обычного ветролиста от ростков до готовых листьев с сохранением уровня рамы |
| `active` | эквивалент `stage04`, готовая грядка текущего уровня |
| `super_stage01-super_stage06` | крупный супер-ветролист с уровневой рамой; на поздних уровнях поддержка должна использовать веревки, ткань, металл или premium-раму по стоимости |
| `construction` | частично собранная рама, видимые материалы текущего апгрейда, ground скопирован из active |
| `damaged` | сломанные части рамы и погнутые листья, но ground остается неизменным |

## Проверка перед приемкой

- PNG всех уровней имеют одинаковый масштаб с ратушами: ширина клетки около `278 px`.
- Ground у всех состояний уровня совпадает с active.
- Нижние грани стоящих деталей касаются земли/рамы/цоколя.
- Нет зазоров между столбами и рейками там, где конструкция должна быть цельной.
- Для каждого уровня есть краткий отчет `resource -> visible element`.
