# Пайплайн Blender-моделей для веб-карты

## Цель

Игровая карта должна быстро показывать много построек на общей изометрической карте. Поэтому Blender-модель хранится как источник и мастер-ассет, а runtime карты использует легкий формат.

## Форматы

| Слой | Формат | Назначение |
| --- | --- | --- |
| Исходник | `.blend` | Редактирование модели, коллекции уровней и состояний, материалы, preview-камера |
| Мастер runtime | `.glb` | Переносимая 3D-модель для инспекции, будущего 3D-превью, каталога построек и проверки ассета |
| Игровая карта | `.webp` или `.png` sprite atlas | Массовый рендер на карте: быстро, стабильно, дешево для браузера |
| Метаданные | `.json` manifest | Соответствие `building type + level + state -> sprite rect / glb path / anchor` |

## Почему не рендерить все `.glb` прямо на поле

Для одной выбранной постройки GLB подходит. Для карты с десятками и сотнями объектов live-рендер 3D-моделей дороже:

- нужен `three.js` или другой GLTF-loader;
- сложнее сортировка по изометрической глубине;
- выше стоимость материалов, света, теней и WebGL draw calls;
- тяжелее обеспечить одинаковый вид на всех масштабах карты.

Практичный вариант для основной карты: рендерить из Blender изометрические кадры в atlas, а `.glb` оставить для детального просмотра, редактора ассетов и будущего 3D-режима.

## Имена ассетов

Имена должны совпадать с внутренними id каталога:

- `dugout_l01_active`
- `dugout_l01_construction`
- `dugout_l01_damaged`
- `wood_house_l06_active`

Состояния:

- `active` - обычная завершенная постройка;
- `construction` - модель со строительным оверлеем;
- `damaged` - поврежденная, но узнаваемая модель;
- `ruined` - можно делать отдельным состоянием позже, пока допустим CSS/overlay поверх `damaged`.

## Manifest

Минимальная структура:

```json
{
  "dugout": {
    "l01": {
      "active": { "atlas": "/assets/buildings/housing/dugout/dugout_atlas.webp", "x": 0, "y": 0, "w": 128, "h": 128, "anchor": [64, 96] }
    }
  }
}
```

`anchor` - точка основания модели в координатах спрайта. Она должна попадать в центр 1x1 тайла.

## Размещение на поле

1. Сервер отдает `type`, `level`, `state`, `tile_x`, `tile_y`.
2. Фронтенд переводит тайл в экранные координаты через `gridToScreen`.
3. Renderer выбирает ассет по `type + clamped(level) + state`.
4. Объект ставится так, чтобы `anchor` совпал с центром тайла.
5. Сортировка по глубине: `z-index` или порядок отрисовки по `tile_x + tile_y`, для больших footprint дополнительно учитывать нижний правый край.
6. Selection, таймер строительства, damage-плашки и ownership-маркеры остаются UI-оверлеями, а не частью базового спрайта.

## Текущий этап

Сейчас карта рендерит здания DOM/CSS-слоем поверх Pixi-тайлов. Для землянки подключен промежуточный компонент `DugoutModel`, который повторяет структуру Blender-модели и выбирает вариант по уровню и состоянию. Следующий шаг ассетного пайплайна - заменить CSS-модель на atlas-спрайты, сгенерированные из `.blend`.
