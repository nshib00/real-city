# Аудит интерфейса перед редизайном

Дата: 30.10.2026. Границы: React-обвязка, навигация, панели, сообщения, UI-ассеты; серверные правила, стоимость, транспорт и игровые 3D-модели сохраняются. Шрифт и fallback-порядок не менять. Карта общего мира остаётся основной поверхностью; стартовая страница только для гостя.

Применены проектные `frontend-design` и `game-ui-design`, включая checklist игровых решений, управления, состояний и доступности. Платформа — браузерная realtime-стратегия; управление мышью, клавиатурой и touch. Контроллер пока вне границ.

## Достоверность результатов

Первый аудит 30.10.2026 выполнялся по исходникам из-за отсутствия Chromium и запрета порта. 31.10.2026 получены четыре снимка текущего App, выполнены DOM/canvas, фокус, touch, DPR/масштабы и контраст. Перекрытия и ошибки исправлены. [Отчёт и ограничения](../frontend/interface-browser-review.md). Пользовательская скорость чтения и историческое сравнение производительности не измерялись.

## Текущая структура

`src/main.tsx` → QueryClientProvider → App → ErrorBoundary → AuthGate. Внутри `game-shell`: ResourceBar, ProfilePanel, ToolBar, MapWidget, BuildMenu, IsoMap, Inspector, ProductionPanel, EventLog, NotificationCenter, ToastCenter, ResourceRegistry, AlliancePanel; дополнительно AudioProvider и условная отладка ассетов. BuildingSync, ResourceNodeSync, MonsterSync, WorldRealtime и ConstructionTicker синхронизируют данные. Их нельзя переносить в декоративный макет или запускать повторно при открытии панели.

Pixi рисует тайлы; Three используется для моделей/предпросмотра. Zustand хранит выбор, режим, камеру и UI-предпочтения; React Query — серверные данные. Визуальная переделка не должна вводить собственную копию authoritative-состояния. Существующий `StrategyInterface.stories.tsx` не является изолированным стендом: открывает панели с API и меняет store при рендере. Новый `design.html` показывает настоящие базовые компоненты без игровой сессии.

## Матрица решений игрока (0.4)

| Решение | Экран / источник | Постоянные данные | Контекстные данные и следующее действие |
|---|---|---|---|
| Наблюдать мир | IsoMap, ResourceBar, MapWidget | Карта, ресурсы, текущий режим, связь | Выбранная клетка, владелец; выбрать / перейти к центру |
| Построить | ToolBar, BuildMenu, placement.ts, Inspector | Карта и доступные ресурсы | Категория, цена, footprint, пригодность клетки, причина запрета; разместить / отменить |
| Разведать | IsoMap, useVisibleChunks, MapWidget | Камера, границы/координаты, связь | Рельеф, лес, ресурсный узел, соседние объекты; переместить камеру / выбрать |
| Защитить / восстановить | Inspector, ThreatPanel, HealthBar | Карта, угроза, остаток ресурсов | Владелец, HP, состояние, защита, ремонт и цена; починить / укрепить |
| Атаковать | Inspector, меню оружия, MonsterSync | Цель, угроза, связь | Чужое владение, HP, оружие/количество, ограничения и ожидание; подтвердить / отменить |
| Произвести / собрать | ProductionPanel, Inspector, поля | Ресурсы и выбранное здание | Рецепт, вход/выход, очередь, готовность, цена; запустить / собрать / отменить |
| Общаться | EventLog → ChatPanel | Доступ к карте, индикатор новых сообщений | Канал, сообщения, отправка/ошибка; отправить / свернуть |
| Восстановить связь | realtime.ts, StatusState, AuthGate | Статус подключения, видимая карта | Reconnecting/offline, ошибка сессии; дождаться / повторить / войти |
| Управлять экономикой и союзом | ResourceRegistry, AlliancePanel | Ресурсы, возможность закрыть панель | Запасы, ордера, казна, полномочия; выполнить разрешённое действие / вернуться к карте |

Приоритет чтения: цель и опасность → доступное действие и цена → результат / серверное ожидание → справочная информация. На touch контекст нельзя делать доступным только через hover. Путь клавиатурой для будущей проверки: карта → инструменты → меню → инспектор → журнал/чат; Escape закрывает верхний слой и возвращает фокус. Это требования приёмки, пока не подтверждение реализации.

## Сверка состояний со спецификацией (0.5)

Спецификация `requirements/design-and-visual-style.md` требует владельца, здоровье, производство, защиту и действия. Требование «атака или рейд» в старом тексте трактуется по AGENTS.md: прямое применение оружия/монстров, без системы рейдов.

| Состояние | Найденная реализация | Пробел / приёмка редизайна |
|---|---|---|
| Своя постройка | Inspector сравнивает `selectedBuilding.owner` с `player.id`, открывает управление | Проверить подпись владельца и форму маркера; не ограничиваться цветом |
| Чужая постройка | Запрос публичного владельца, отдельный `canAttackSelectedBuilding`, оружие | Сохранить раздельные действия; проверить загрузку/ошибку профиля владельца |
| Нейтральный объект | Ресурсные узлы, рельеф и монстры отображаются отдельно от зданий | Не обозначать отсутствие выбранного владельца как враждебность; отдельная подпись ресурса |
| Строительство | `status === 'construction'`, ConstructionTicker, ускорение/отмена, remaining time | Таймер и стоимость должны оставаться видны, disabled должен иметь причину |
| Урон / разрушение | HealthBar, `state` damaged/ruined, расчёт maxHealth, ремонт/восстановление | HP уже семантический progressbar; добавить проверку различимости состояния без цвета |
| Угроза | ThreatPanel / threats query, монстры и цель атаки | Проверить приоритет на фоне карты и отсутствие коллизии с ownership-цветом |
| Нехватка ресурсов | Inventory и цены действий; доступность рассчитывается в контекстных компонентах | Единый формат «нужно / имеется / не хватает», server rejection и pending проверить отдельно |
| Недопустимое размещение | placement.ts проверяет выбор, первую/единственную ратушу, занятость, монстра и рельеф | Сохранить текст причины рядом с preview; сервер остаётся авторитетным |
| Offline / reconnect | realtime client имеет connecting/connected/reconnecting/offline; StatusState имеет offline | Наличие вариантов не доказывает блокировку всех мутаций; проверить каждый критический путь |
| Пустой выбор | Inspector работает с выбранным/hover-тайлом; действия требуют activeTile/цель | Touch не должен зависеть от hover; показать понятное «Выберите клетку» |
| Pending / ошибка действия | Мутации Inspector отключают кнопки через isPending, отдельные сообщения ошибок | Проверить повтор и отсутствие двойного расхода; общая анимация не заменяет подтверждение сервера |

## Риски, найденные по CSS и компонентам

Это проверяемые гипотезы, а не дефекты, подтверждённые снимками.

| Приоритет | Наблюдение по исходникам | Проверка / следующая фаза |
|---|---|---|
| Высокий | При ≤760px `.inspector .tabs` и `.inspector-actions` имеют `display:none`; инспектор фиксирован высотой 104px | Пройти основные действия touch, раскрываемый инспектор в 5.2 |
| Высокий | Инструменты bottom 122px, журнал bottom 126px и занимает до 168px | Измерить пересечения bounding-box при открытом/закрытом журнале; 3 и 5 |
| Высокий | При ≤1180px ресурсы начинаются с left 72px; профиль сохраняет ширину 248px | Проверить перекрытие на 1024×768; затем 3.1 |
| Средний | Верхняя строка горизонтально прокручивается; часть подписей и realtime-chip скрыта при ≤900px | Проверить доступ к последним ресурсам и альтернативному статусу связи |
| Средний | IconButton даёт aria-label/title/pressed, но не принимает текст причины disabled | При унификации компонентов предусмотреть доступную причину и touch-подсказку |
| Средний | Жёсткие offsets верхних и нижних панелей, ограничение инспектора по высоте | Проверить 200% текст, длинные русские строки, safe-area и экранную клавиатуру |
| Средний | Текущие панели и фоновые стили распределены в большом index.css | Выделять токены/компоненты постепенно, без смены гарнитуры; 2 |

Контраст пока не измерен: нужны реальные composited-пиксели над травой, водой, руинами и зданиями. Цель — 4.5:1 обычный текст, 3:1 крупный текст/контролы. Не утверждать соответствие по одним hex без прозрачности и подложки.

## Финальная приёмка интерфейса — 01.11.2026

Повторяемая автоматизация включена в `.github/workflows/browser-e2e.yml`: изолированный React/Pixi smoke, theme pixel baselines на 390/1440 px и live API/WS сценарии на desktop/mobile. В `.github/workflows/frontend-ci.yml` входят типы, unit, production build и бюджет ассетов. Изолированный сценарий переключения тем проверяет сохранение canvas, выбранной клетки и черновика чата, а также отсутствие игровых mutation-запросов. Live smoke после входа дополнительно переключает обе темы, проверяет сохранность canvas и отсутствие mutation-запросов, затем продолжает строительство и сбор по реальному API при активном WebSocket. Серверная игровая логика/контракт не меняются темой. `VITE_INTERFACE_THEME_DEFAULT` настраивает тему только для нового устройства; сохранённый выбор имеет приоритет.

| Доступность | Browser review проверяет клавиатуру, 200% текст, reduced motion, имена контролов и touch-геометрию. Нужны физический мобильный проход и проверка реальным экранным диктором (8.4). |
