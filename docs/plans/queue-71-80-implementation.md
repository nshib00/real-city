# Очередь 71–80: выполненные изменения и проверки

Дата: 01.11.2026. [Постановка](queue-71-80.md). Проверки проводились в `golang:1.24-alpine` с Go 1.24.13 и на работающем тестовом Compose. Для race-проверки в одноразовый контейнер установлены `gcc` и `musl-dev`. Внешний production и чужие данные не затрагивались.

| № | Результат |
|---|---|
| 71 | Тест DTO сверяет число типов с текущим серверным каталогом и все уровни каждого типа. Убран устаревший литерал `73`; живой smoke больше не требует фиксированного числа типов и проверяет отсутствие дублирующих ID. |
| 72 | `go build ./cmd/...` и обычный `go vet ./...` проходят. Исправлены 86 предупреждений `composites` в трёх файлах каталога: все соответствующие стоимости и количества ресурсов имеют именованные поля. Числа и рецепты не менялись. |
| 73 | `go test ./...` и `go test -race ./...` проходят. Первый race-прогон выявил ответ `503` при смене пароля: bcrypt на инструментированном медленном CPU превышал общий лимит 5 с. Лимит увеличен до 15 с, повторный прогон зелёный. |
| 74 | В отдельной БД `real_city_queue71` применены миграции `000001`–`000053`; второй запуск мигратора не применил ни одной, итоговая таблица содержит 53 версии, минимум 1, максимум 53. Основная тестовая БД не очищалась. |
| 75 | Тесты кеша проверяют повторный JSON, изменение ETag после изменения тайла, вытеснение по памяти/числу записей и конкурентные чтения/записи под race detector. |
| 76 | Существующий тест пробуждения AI через шов мира проходит. Тест кеша построек дополнен удалением объекта между тиками: следующий тик не возвращает удалённую постройку. |
| 77 | Go-тест ping → pong → следующая команда проходит. Живой smoke дважды подключается к WS с одним токеном после закрытия первого соединения; повторное подключение принято. Длительный разрыв и массовый fanout этим не проверены. |
| 78 | Скрипт архива отвергает `--apply` без нового пути архива **до обращения к БД**. Два Python-теста подтверждают защиту и то, что dry-run при 42 подходящих строках делает только подсчёт. На текущей тестовой БД строк до выбранного cutoff не оказалось (0 до и после вызова); удаление не выполнялось. |
| 79 | Живой `smoke.py` прошёл после пересборки backend в прежнем Compose-профиле `real-city-test`: регистрация двух игроков, мир/каталог, размещение и повтор команды, инвентарь, монстры, оружие и повтор атаки, WS и повторное подключение. Прогон добавил тестовых пользователей и постройки в тестовую БД. |
| 80 | Этот отчёт, очередь, основной план и аудит производительности обновлены по фактам проверок. Новых замеров p95/CPU/heap этим прогоном не получено. |

## Команды

```sh
docker run --rm -v "$PWD:/work" -v real-city-go-mod:/go/pkg/mod -v real-city-go-build:/root/.cache/go-build -w /work/backend golang:1.24-alpine sh -c 'go build ./cmd/... && go vet ./... && go test ./...'
docker run --rm -v "$PWD:/work" -v real-city-go-mod:/go/pkg/mod -v real-city-go-build:/root/.cache/go-build -w /work/backend golang:1.24-alpine sh -c 'apk add --no-cache gcc musl-dev >/dev/null && CGO_ENABLED=1 go test -race ./...'
python3 -m unittest scripts/test_archive_monster_moves.py
python3 tests/e2e/api/smoke.py
```

Миграции запускались бинарником `/app/migrate` в тестовом backend-контейнере с отдельным `POSTGRES_DSN`. После первого `up` и повторного `up` проверен `SELECT count(*), min(version), max(version) FROM schema_migrations` → `53|1|53`.

Тестовый backend пересобран командой `docker compose -p real-city-test -f docker-compose.test.yml -f docker-compose.laptop.yml up -d --build backend`. Существующие тома PostgreSQL/Redis сохранены. Отдельный пустой Compose-стек, созданный при первоначальном запуске без имени проекта, остановлен; его новые пустые тома удалены.

## Открытый объём приёмки

Эта очередь закрывает перечисленные точечные проверки, но не закрывает целиком 31–40: не выполнены SQL-конкурентные сценарии с ошибками между шагами, нагрузка 100–1000 WS-клиентов, CPU/heap-профиль AI, p95 просрочки на 1000/10 000 монстров, длительный разрыв соединения, мобильный браузер и production-откат. Изолированная БД после проверки оставлена для сверки результатов; она не используется приложением.
