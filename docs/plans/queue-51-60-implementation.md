# Реализация очереди 51–60: фактическое состояние

Дата: 30.10.2026. Основание: [очередь](queue-51-60.md). Все десять пунктов целиком **не завершены**. Серверный барьер 31–32 остаётся открытым: Go отсутствует в PATH, Docker daemon недоступен, Vite не может слушать 127.0.0.1:5173 (`EPERM`). Новые серверные механики и контракты не вводились. Рабочая БД и production не изменялись.

## 51. Цикличность карты — частично

На границе клиентского API нормализованы координаты чтения чанков, viewport, видимых построек, монстров, угроз, добычи монстров и присутствия игроков; также размещение, перенос постройки и рубка леса. Координаты чанка нормализуются в единицах чанков, остальные — клеток. Эквивалентные координаты через швы/угол покрыты API-тестами. Сервер по-прежнему обязан самостоятельно валидировать все действия.

Осталось: Go-тесты серверной нормализации/дальности/pathfinding/AI, browser-переходы через оба шва, сохранение выделения и 60-секундная приёмка камеры. Изменение клиента само по себе их не подтверждает.

## 52. Snapshot/delta видимой области — не реализовано

Сохраняется имеющийся протокол WS с последовательностью соединения, resync при gap/reconnect и HTTP-чтением активных запросов. Новые cursor/version, tombstones и ленивый inspector не добавлялись. Нет исходных серверных замеров пункта 39 и пройденного барьера 31–32, поэтому новый протокол не объявлен готовым. Нужно отдельно проверить гонку HTTP snapshot с WS, удаление объектов и совместимость развёртывания; затем измерить payload до/после.

## 53. Кэш проекций — не реализовано

Redis cache-aside не добавлен. Без измерения горячих чтений и SQL-тестов нельзя подтвердить корректную post-commit инвалидацию, rollback и восстановление Redis. Нужны отдельные ключи версии каталога и проекции чанка, исключение прав/расчётов из кэша, защита конкурентного заполнения, тесты отказа и hit/miss/error без ID в labels. Существующий клиентский TanStack cache не считается реализацией серверного пункта.

## 54. Производственные цепочки — подготовлен инструмент проверки источников

`tools/production/audit_sources.py` строит замыкание гарантированных выходов рецептов из versioned balance v2 и всех вариантов уровней. Учитывает входы и обязательное топливо, выдаёт отсутствующие ресурсы и производителя каждого достигнутого ресурса. Случайные награды не выдаются за гарантированный источник. Есть три теста: топливная циклическая блокировка, открытие цепочки внешним источником и исключение редкого выхода.

Пример:

```bash
python3 tools/production/audit_sources.py \
  --sources tools/production/forest-town-hall-sources.json \
  --output /tmp/real-city-production-sources.json
python3 -m unittest discover -s tools/production -v
```

Пример источников описывает монеты/ножи стартового инвентаря, древесину после рубки и жителей ратуши. Это **не полный список** добычи мира. На этом ограниченном наборе анализируются 267 вариантов рецептов/уровней, 241 требует дополнительных источников. Это диагностический результат, а не 241 подтверждённый баг: отдельные динамические рецепты, месторождения, поля, торговля и случайные награды требуют явного моделирования. Также пока не учитываются стоимость/достижимость построек и уровней, объём запасов, рабочие, склады, XP и вероятность. Полная достижимость и серверные причины остановки не реализованы; баланс не менялся.

## 55. Клиентская телеметрия — локальный канал готов, удалённого сбора нет

Добавлены фиксированная схема и версия клиента, runtime/Promise/asset/render-сигналы, WS reconnect/recovery/gap. Окно дедупликации — минута, очередь — 32 записи, отправка — раз в 30 секунд/online. Очистка при смене аккаунта, исключение повторного добавления старой неуспешной отправки, отсутствие рекурсивного retry покрыты тестами. Браузерные события проверяются без передачи сообщения исключения, URL и ID.

Приёмник — локальное событие `real-city:client-telemetry`; удалённого endpoint, хранения и централизованных оповещений нет. Инструкция и ограничения: [диагностика клиента](../operations/client-diagnostics.md). Для закрытия пункта нужны серверный sink и сквозная приёмка offline/reconnect/account change.

## 56. Игровые метрики и оповещения — не реализовано

Новые серверные counters, Redis exporter, централизованные логи и alerts не добавлялись. Существующие технические dashboards/alerts сохранены. Клиентский локальный диагностический канал не подменяет мониторинг.

Перед реализацией закрепить семантику: считать подтверждённые фиксации действий, не запросы/WS-повторы; повтор идемпотентного запроса не увеличивает число действий. Process counters обнуляются при рестарте, для частот использовать `rate/increase`; постоянные итоги получать из БД. Labels — только фиксированные типы действия/результата/ресурса, без player/building/event ID. Срабатывание и recovery проверять на изолированном стенде после реализации диагностики 48 и приёмника 55.

## 57. Production-защита — конфигурация подготовлена, приёмка открыта

Backend Dockerfile: CA, пользователь UID/GID 10001. Compose: read-only rootfs, ограниченный tmpfs, сброс capabilities, no-new-privileges. Caddy: закрыты публичные metrics/debug, ограничение тела API 1 MiB, дополнительные заголовки безопасности. Dockerignore обоих контекстов исключает env/PEM/ключи; шаблон окружения разрешён.

Осталось проверить build и runtime, Caddy validation, HTTPS/API/WS, Origin, истечение токена, таймауты, отсутствие stack trace/секретов и репетицию 40. Web-контейнер пока не non-root. Синтаксический разбор YAML не подтверждает применимость production-конфигурации. [Подробности](../operations/quality-and-release.md).

## 58. Проверки качества — частично

Добавлен `scripts/check-quality.sh`: полный режим требует настоящий Go и запускает gofmt/vet/race/build, существующие контракты, frontend typecheck/tests/build; режим frontend явно ограничен клиентом. В frontend CI добавлены typecheck и блокирующий high/critical production `npm audit`. Политика и пробелы описаны в [инструкции](../operations/quality-and-release.md).

Отдельные frontend lint/formatter, backend lint/security, механизм исключений и успешный удалённый CI-run не реализованы. Локальный npm audit не завершил аудит: registry недоступен. Ошибка сети не считается отсутствием уязвимостей. Full quality завершается ошибкой из-за отсутствия Go.

## 59. Образы и развёртывание — локальный сборщик подготовлен

`scripts/build-release-local.sh` собирает два образа из чистого commit, добавляет revision, фиксирует локальные image ID и не публикует/развёртывает их. Манифест явно имеет статус `built-not-scanned-or-deployed`; image ID не назван registry manifest digest. Нельзя получить новый успешный манифест после сбоя одной из сборок.

Сборка не выполнена из-за Docker permissions. Сканирование, SBOM/provenance, registry digest, воспроизводимость образов, health и rollback ещё требуют реализации/приёмки. Переиспользуются существующие инструменты 40, но их успешный прогон здесь не заявляется. Внешняя публикация и live production не выполнялись.

## 60. Звук — исправлено ограничение памяти дедупликации

Обнаружен дефект в двух окнах event ID: при интенсивном потоке удалялись только старые по TTL записи, поэтому фактического предела размера не было; при редком трафике TTL не проверялся. Общий `AudioEventWindow` проверяет TTL при каждом событии и жёстко вытесняет самые старые записи сверх лимита. Пределы сохранены: WS — 2000/120 секунд, combat voices — 500/60 секунд. Тесты проверяют burst, replay и истечение при редких событиях. Это ограниченное окно, а не бессрочная гарантия дедупликации.

Аудиокаталог прошёл валидатор: 146 звуков, 307 файлов. Полная матрица прямого PvP, HTTP/WS/reconnect, autoplay/gesture/mute/background/mobile и реальное прослушивание ещё не приняты. Исправление дедупликации не закрывает весь пункт.
