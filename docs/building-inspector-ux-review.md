# Разбор правого меню постройки

## Область разбора

Панель инспектора справа (`Inspector`) показывает выбранную клетку, постройку или монстра. Для выбранной постройки в ней есть заголовок, блок контекста, вкладки «Клетка»/«Объект», карточка параметров и отдельная полоса действий. Ниже — аудит текущего интерфейса и план упрощения; это предложение по UX, без изменения поведения игры.

## Что повторяется сейчас

| Данные или действие | Где дублируется | Почему мешает |
| --- | --- | --- |
| Название постройки | Заголовок панели и жирная строка карточки «Объект» | Занимает место и визуально создаёт два заголовка одного объекта. |
| Здоровье | В блоке контекста, текстом в карточке и полосой `HealthBar` | Одно значение показано до трёх раз; сложно понять, какой элемент главный. |
| Состояние | Значок статуса в `ObjectMarks`, текст состояния в карточке, пояснение в контексте; для стройки/ремонта есть ещё таймер | Статус распылён между секциями и повторяется. |
| Владение | Маркер владения `ObjectMarks`, подпись «Ваша/Союзная/Чужая постройка» и строка владельца в карточке | Несколько раз сообщается одна и та же принадлежность. Профиль владельца полезен только для чужих построек. |
| Улучшение | Кнопка «Открыть улучшение» в контексте, кнопка улучшения в панели действий и подсказка, что улучшение выполняется из меню постройки | Дублируются входы в одно действие; подсказка звучит как инструкция вместо информации о состоянии. |
| Осмотр объекта | Кнопка «Осмотреть постройку» переключает на вкладку «Объект», которая уже есть в этой же панели | Лишний переход и отдельное действие для открытия содержимого текущего меню. |
| Атака | «Выбрать оружие» в контексте, кнопка атаки в панели действий, а также отдельная вкладка с данными объекта | Несколько одинаковых точек входа; главная команда не выделена однозначно. |
| Строительство/ремонт | Текстовое состояние, таймер и пояснение о том, где посмотреть оставшееся время | Состояние и оставшееся время лучше показывать вместе один раз. |

## UX-проблемы помимо дублей

- Панель смешивает сведения о клетке и выбранной постройке в соседних вкладках. При выборе постройки вкладка «Объект» включается автоматически, но игроку всё ещё доступны данные клетки, которые не относятся к управлению зданием.
- Обзорные и редко нужные параметры занимают одинаковое визуальное место. Например, радиус пушки и её боезапас важны для боевого здания, а поворот и подробности владельца нужны значительно реже.
- Полоса действий показывает набор иконок без группировки. Для разных типов зданий она меняется, поэтому игроку приходится заново распознавать расположение команд.
- Ряд кнопок остаётся иконками; понятные текстовые подписи могут быть доступны только через подсказки. Это хуже для первого знакомства и сенсорного управления.
- В карточке есть служебные формулировки вроде «Улучшение выполняется из меню этой постройки», хотя игрок уже находится в меню постройки.

## Предлагаемая структура панели

1. **Шапка:** название и уровень; строка состояния с короткой подписью, например «Работает», «Повреждена на 18%», «Строится · 02:14». Не повторять название ниже.
2. **Здоровье:** одна полоса с числом внутри или рядом. Убрать отдельное текстовое дублирование и дополнительный статус, который уже очевиден из полосы, кроме случаев, когда нужно объяснить особое состояние.
3. **Главные действия:** компактный ряд с текстовыми подписями и только доступными сейчас командами. Порядок постоянный: основное действие по типу здания, затем улучшение/атака, затем обслуживание. Перенос, поворот и удаление — во вторичный раздел действий.
4. **Сведения:** показывать только параметры, нужные для выбранного типа и текущего состояния. Для пушки оставить радиус, урон и режим автоатаки; боезапас, перезарядку, цель и гарнизон раскрывать в блоке «Орудие». Для поля показывать фазу и срок до следующего этапа; готовый сбор выводить как основную команду.
5. **Дополнительно:** поворот, владелец и ссылка на профиль, подробные боевые параметры, предпросмотр 3D — в сворачиваемом разделе. Владельца показывать только для чужой постройки; маркера владения достаточно для своей.
6. **Клетка:** при выбранной постройке убрать вкладку «Клетка» из основного сценария. Координаты можно оставить одной компактной строкой внизу карточки или в дополнительном блоке.

## Правила показа действий

- Отображать только применимые действия; неприменимые команды скрывать, а не оставлять отключёнными без объяснения.
- **Своя работающая постройка:** действия по её типу, улучшение при доступном уровне, перемещение и поворот, удаление во вторичном меню.
- **Своя повреждённая постройка:** добавить ремонт с ценой/условиями. Не показывать ремонт для полной прочности или разрушенной постройки.
- **Строящаяся постройка:** оставить прогресс и оставшееся время; показать ускорение и отмену строительства. Убрать перемещение, поворот и обычные действия, пока они недоступны.
- **Чужая постройка:** показать владельца и основные сведения; единственное главное действие — атака, если цель уязвима. Не показывать управление своей постройкой.
- **Специализированная постройка:** её повседневное действие (сбор урожая, переключение орудия, перезарядка ловушки) должно появляться на одном и том же месте среди главных команд.

## План упрощения по этапам

### Этап 1 — убрать очевидные повторы

- Удалить второй заголовок из карточки.
- Оставить один способ отображения здоровья.
- Убрать блок контекста с кнопкой «Осмотреть постройку» и перенести единственную основную команду в ряд действий.
- Удалить инструктивные сообщения, которые описывают уже очевидное действие или расположение меню.
- Объединить статус и таймер строительства/ремонта в одной строке.

### Этап 2 — упорядочить команды

- Сгруппировать действия на основные и дополнительные.
- Основным действиям дать короткие подписи рядом с иконками, чтобы панель была понятна без наведения.
- Перемещение, поворот, удаление, 3D и прочие редкие команды поместить в компактное меню «Ещё».
- Сохранить текущие проверки доступности: повреждение для ремонта, состояние и уровень для улучшения, права владельца для управления, уязвимость цели для атаки.

### Этап 3 — упростить чтение параметров

- Убирать вкладку «Клетка» при выборе постройки, оставляя её только для выбранной пустой клетки/ресурсного узла/руин.
- Свернуть редкие параметры орудий и защитных построек в типовой блок подробностей.
- Сохранить на виду только параметры, которые помогают принять следующее решение: состояние, прогресс, готовность к действию и краткие характеристики объекта.

## Критерии хорошего результата

- Игрок видит название, текущее состояние и следующее полезное действие без прокрутки.
- Каждое часто нужное действие имеет ровно одну очевидную точку входа.
- Здоровье и состояние не повторяются в нескольких секциях.
- Для своей, союзной и чужой постройки отображаются разные наборы команд согласно правам.
- Сбор, ремонт, ускорение и атака показываются только в подходящем состоянии.
- На узком экране основные действия остаются читаемыми и доступными без попадания в длинный список второстепенных кнопок.
