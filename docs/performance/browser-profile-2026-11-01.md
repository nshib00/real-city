# Браузерный профиль интерфейса — 01.11.2026

## Прогон

Автоматический smoke в Chromium, DPR 1, с реальными React/Pixi и ассетами фронтенда. 01.11.2026 один синтетический dev-сценарий повторён на viewport 1440×900 и 390×900; API и WebSocket изолированы фикстурами `mockInterfaceWorld`. Сцена: `?perf=mixed&perfBuildings=100&perfMonsters=30&perfResources=50&perfTileRadius=16`. 390 px — эмуляция ширины телефона на desktop Chromium, не физический телефон.

Результат снят `browser-review.spec.ts`, тест «профиль карты: загрузка, кадры, реакция на действие и перекрытие UI». Команда:

```sh
npm run test:ui-review -- --project=390-dpr1 --project=1440-dpr1 -g 'профиль карты'
```

## Результаты

| Метрика | Результат | Как измеряется |
|---|---:|---|
| Готовность canvas и HUD, desktop 1440×900 | 1 837 мс | От начала `page.goto` до видимых canvas и performance HUD; API отвечает фикстурами |
| Готовность canvas и HUD, mobile viewport 390×900 | 1 583 мс | Та же методика; viewport эмулирован на desktop Chromium |
| CSS, шрифты и изображения | 128 784 байта, 67 ответов | На обоих viewport; тела ответов браузера без HTTP-сжатия |
| Кадры, desktop | 53,8 FPS; p50 16 мс; p95 19 мс | 5 секунд `requestAnimationFrame`; интервал кадров, не CPU-время рендера |
| Кадры, mobile viewport | 57,2 FPS; p50 16 мс; p95 18 мс | Та же synthetic сцена и Chromium, изменён viewport |
| Реакция карты на увеличение, desktop / mobile viewport | 523 / 410 мс | От запуска Playwright click до изменения CSS transform; включает автоматизацию и не является пользовательским input latency |
| Закрытая интерфейсом площадь карты, desktop / mobile viewport | 49,68% / 60,95% | Геометрическое объединение пересечений панели с картой; на mobile доля выше из-за меньшей площади viewport |

Перекрытие вычисляется геометрически: прозрачность и реальная видимость карты под панелями не учитываются, поэтому это верхняя оценка занятой площади. Длительность реакции включает доставку клика через браузерную автоматизацию. Для оценки пользовательской задержки на физическом устройстве нужен независимый прогон.

## Сопоставление и ограничения

В [аудите производительности](performance-audit.md#повторные-измерения) зафиксированы размеры production `dist/assets` и главного JS до/после оптимизаций: 959,11 → 812,21 МиБ для всей поставки, 492,02 → 468,78 КБ для главного JS. Эти значения не сравнивают тему редизайна. Предыдущие browser frame samples сняты в другой сессии и не являются A/B-парой; вывод об улучшении FPS не делается.

Это сопоставимый dev-срез desktop/mobile viewport, но один прогон на размер без прогрева, production-сборки и физического телефона; FPS и задержку нельзя трактовать как device-neutral A/B. Для завершения 8.5 нужны три прогретых production-прогона на каждом целевом устройстве и строгая пара старой/новой версии с одинаковыми браузером, GPU, viewport, ассетами и действиями. Такой парный прогон и traces пока не получены.
